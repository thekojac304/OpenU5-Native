# D-89 (naval/cactus OUCH routine) -- investigator B, "ports first" lens

Everything below marked BINARY was disassembled in this session with `re/tools/dis16.py`
(capstone, 16-bit; `--exe` for ULTIMA.EXE so offsets equal the notes' CS:IP) and cross-checked
with scratch scripts in the findings folder (`census.py`, `bases.py`, `reach2.py`, `ctx.py`,
`fn.py`, `mf_cactus.ts`). Nothing in the repo was modified; no build/ctest was run.

---------------------------------------------------------------------------------------------

## 1. Verdict

1. **The original has ONE cactus-OUCH site, shared by foot, horse, carpet, skiff and a rowing
   frigate.** It is `MAINOUT.OVL 0x0336  call 0xffffa8d8` = kernel `0x2AA8`
   (`kernel_party_random_damage`). It takes no arguments and **loops over the party**: one
   `rand(1,8)` per member whose status byte is not `'D'`, among the first `min(party_size,6)`
   slots, each followed by that member's own apply_damage (`0x2A52`: row flash, noise burst,
   HP subtract, death handling, panel redraw).
2. **Native is wrong for the naval case, and so is the TypeScript reference's *code*.** Both
   ports roll a single `rand(1,8)` against the *active* member only:
   - native `native/core/src/commands.cpp:372-382` (`naval_step`),
   - TS `game/src/core/game.ts:1929-1933` (`resolveNavalStep`, `res.partyDamageRoll`).
   The notes (`re/notes/cactus-ouch-acta.md`), the TS *comments*, the TS **foot** path
   (`game.ts:1520-1526`) and the native **foot** path (`commands.cpp:498-506`) are all right:
   they call `partyRandomDamage` / `party_random_damage`. So the ledger wording "the reference
   says the original calls party_random_damage" is true of the reference's foot path and docs,
   but the reference's naval code does the same direct active-member roll as native: **both
   ports move, the notes do not.**
3. What "naval" means in the binary: there is no separate naval routine. `ship_try_move`
   (MAINOUT `0x01FE`) is the single step-resolution routine for every transport. The OUCH is
   reached only through the *non-sailing* blocked tail (`0x0312-0x0347`), i.e. a **skiff
   (0x28-0x2b) or a frigate with sails furled (0x24-0x27) pushing against a destination
   whose terrain tile is 0x2f**. A frigate with sails up (g_sail_dir != 0) hitting a cactus
   goes to the sailing branch instead: "COLLISION!" + `rand(1,30)` hull damage, no OUCH.
4. **Practical reachability:** in the shipped data the naval-cactus case cannot occur. The 14
   Britannia cacti (computed below) are all ringed by desert tile 0x07; UNDER.DAT has none;
   the only town map with cacti (Sin Vraal's Hut) has no navigable tile. It is reachable only
   synthetically (unit tests, the movement-flow corpus, Developer teleport). The fix is
   therefore parity-clean and invisible in normal play; it matters for fidelity of the code
   and for the corpus.
5. Status/death behaviour follows the helper: dead members are skipped with no draw; sleeping
   (`'S'`) and poisoned (`'P'`) members are damaged and keep their status (no wake); HP <= 0
   (signed word compare) sets HP 0 and status `'D'`, and clears the active-character slot if
   the dead member was active.
6. Text/SFX: `"Blocked!\n"` (DS 0x29ae) then `"OUCH!\n"` (DS 0x29b8), no beep (the beep is the
   `else`), no clock tick (the caller skips the tick on a blocked move), type-ahead flushed.

Confidence: **high** for routine identity, call-site census, draw count/order, status
behaviour, text. **Medium** for the adjacent "no clock tick on a blocked rowing step" claim
(section 8, A1): derived from the dispatcher, not witnessed live.

## 2. Binary facts

### 2.0 Tooling controls and base arithmetic (done before trusting anything)

- **C1, rand formula.** `ULTIMA.EXE 0x2092` disassembled:
  ```
  2098 mov ax,[0x5420]   209b add ax,0x9248   209e/20a0/20a2 ror ax,1 x3
  20a4 xor ax,0x9248     20a7 add ax,0x11     20aa mov [0x5420],ax
  20ad and ax,0x7fff     20b0 mov bx,[bp+6]   20b3 mov cx,[bp+4]
  20b6 sub cx,bx  20b8 inc cx  20bb div cx  20bd add dx,bx   ; ret 4
  ```

  = `lo + ((x & 0x7fff) % (hi-lo+1))`, `[bp+6]=lo`, `[bp+4]=hi`. Identical to

- **C2, overlay near-call base.** MAINOUT's print calls (e.g. `0x0212`, `0x0326`, `0x0333`)
  `call 0xffff9680` resolve to
  `(0x9680+0x81d0)&0xffff = 0x1850`; `ULTIMA.EXE 0x1850` has a prologue and is the string
  printer (`cmp byte [bx],0` on the string pointer arg). `call 0xffffa0f0 -> 0x22c0` is the

  `55 8b ec` prologue. So MAINOUT's base **0x81D0 is verified**.
- **C3, tool base table is partly wrong.** I scored every overlay's near calls against the set
  of kernel prologues that the kernel itself calls (`bases.py`). Data-driven best bases:

  `callers_banda.py` BASES) is wrong for OUTSUBS (says 0x81D0) and DUNGEON (says 0xE1E0) and
  a few others. Consequence: **`callers_banda.py 2aa8` misses OUTSUBS 0x05f8 and the three
  DUNGEON sites.** I used a corrected census (section 3). Positive control for the census:
  it finds the known starvation caller `ULTIMA.EXE 0x2b74` and the known OUTSUBS 0x05f8

- **C4, 0x1fe has exactly one caller; thunk table has no entry for it.** See section 3.

### 2.1 `ship_try_move` MAINOUT 0x01FE (all modes), the part that matters

Arguments (from the caller 0x0490): `[bp+6]=dx`, `[bp+4]=dy` (each -1/0/+1; caller pushes
`[bp-4]` then `[bp-6]`, and in 0x0490 case 1 `dec [bp-4]` prints "West", case 3 `dec [bp-6]`
prints "North"). Returns `[bp-2]`: 1 = step OK, 0 = no move.

```
01fe push bp / mov bp,sp / sub sp,6 / push si
0205 mov al,[0x587c]          ; g_transport_tile
0208 and al,0xfc ; 020a cmp al,0x24 ; 020c jne 0x215
020e mov ax,0x2982 ; push ; call 0xffff9680       ; "Rowing!\n"  (rowing frigate only)
0215 mov [bp-2],1
021a..022f  y' = dy + [0x5897], x' = dx + [0x5896], push y',x', [0x5895](floor)
0236 call 0xffffb4be  -> kernel 0x368e find_object_at_xy ; [bp-4] = actor tile or 0
023c or ax,ax ; je 0x288
0240 mov [bp-2],0           ; an actor stands there -> blocked unless boardable
0245..0283  boardable tests (may set [bp-2]=1)
0288 si=[bp+4]<<5 ; bx=[bp+6] ; al=[bx+si-0x5459] (=0xABA7+dy*32+dx)
0298 mov [bp-6],ax         ; [bp-6] = DESTINATION TERRAIN TILE (not the actor)
029b cmp [bp-2],0 ; je 0x2b4
02a1 push [0x587c] ; push [bp-6] ; call 0xffffaa7c -> kernel 0x2c4c   ; passable(transport,tile)
02ab or ax,ax ; je 0x2b4 ; 02af mov ax,1 ; jmp 0x2b6
02b4 sub ax,ax
02b6 mov [bp-2],ax ; or ax,ax ; je 0x2c0 ; 02bd jmp 0x34a      ; passable -> return 1
02c0 cmp byte [0x5955],0 ; je 0x312        ; g_sail_dir: nonzero => SAILING branch
02c7..030b  sailing: [bp-6]==3 "BREAKING UP!"(0x298b) / !=0x47 "COLLISION!"(0x2999) /
            ==0x47 "Docked!"(0x29a5)+add [0x587c],4 ; collision path: push 0x64,0x7d0,0x12c ;
            call 0xffffa06c (noise burst) ; call 0x109e (damage_ship) ; 0306 [0x5955]=0
0312 cmp byte [0x587c],0x20 ; jb 0x322       ; vehicle threshold (< 0x20 = foot/horse/carpet)
0319 mov al,[bp-4] ; and al,0xfc ; cmp al,0xec ; je 0x34a   ; vehicle vs whirlpool actor: SILENT
0322 mov ax,0x29ae ; push ; call 0xffff9680                  ; "Blocked!\n"   (ALWAYS)
0329 cmp word ptr [bp-6],0x2f ; jne 0x33c                    ; DEST TERRAIN == cactus ?
032f mov ax,0x29b8 ; push ; call 0xffff9680                  ; "OUCH!\n"
0336 call 0xffffa8d8        ; -> kernel 0x2AA8 party_random_damage  (no args, no pushes)
0339 jmp 0x347
033c mov ax,0xa5 ; push ; mov ax,0xc8 ; push ; call 0xffffa0f0   ; beep(0xa5,0xc8) -- ELSE only
0347 call 0xffff9946        ; -> kernel 0x1b16 keyboard type-ahead flush (writes 0040:001a/001c=0x1e)
034a mov ax,[bp-2]          ; 0 for every blocked outcome
0351 ret 4
```
DS strings (DATA.OVL fileoff = DS + 0x10), read from the file: 0x29ae `Blocked!\n`,
0x29b8 `OUCH!\n`, 0x2982 `Rowing!\n`, 0x298b `BREAKING UP!\n`, 0x2999 `COLLISION!\n`,
0x29a5 `Docked!\n`.

Consequences (all from the listing above):
- The cactus test is on the **terrain tile** `[bp-6]` (a word compare against 0x2f, so no
  width/sign issue), independent of whatever actor blocked the step.
- It is **below** the `[0x5955]` (sailing) test and the `[0x587c] < 0x20` test: a sailing
  frigate never reaches it; foot/horse/carpet jump straight to 0x0322.
- Passability: I evaluated `kernel 0x2c4c` (+ `0x2bd4`, `0x2c2e`, bit table `DS 0x54d4`,
  class table `DS 0x54f4`) for tile 0x2f and transports 0x10, 0x14, 0x18, 0x1c, 0x20, 0x24,
  0x28: **impassable for all** (bit table byte for tile 0x2f is 0xf3, bit 0x01 set). So the
  tail is always reached. (`scratchpad`: inline python, emulation of 0x2c4c's classes 0-3,
  5-6; class 4 not evaluated, irrelevant to these transports.)

### 2.2 Who calls 0x01FE and what happens after it returns

- Only caller: `MAINOUT 0x0514` inside `outdoor_move` MAINOUT `0x0490` (case dispatch on the
  key code 1=W,2=E,3=N,4=S: `0x04f0` etc.). `0x0490` is itself called only from the command
  dispatcher at `MAINOUT 0x0bb3` (`push [bp-4]` key, `push [bp-2]`, `call 0x490`, `jmp 0xc0f`).
- Before it: `0x0490` calls the facing helper `0x00da` (class switch 0x10/0x14/0x20/0x24/
  0x28) for each direction; a nonzero return aborts the step (frigate turning, "Head ...");
  the skiff helper returns 0 so a skiff turns **and** steps in the same key. After a zero
  return `0x0500` prints the direction word (DS 0x29db North / 0x29e2 South / 0x29e9 East /
  0x29ef West) when `[0x5955]==0`, then `call 0x1fe` (0x0514).
- After it: `0x0517 mov [bp-2],ax ; 051a cmp [bp+4],0 ; jne 0x53c ; or ax,ax ; je 0x53c`
  then (only on success) `0x0536 call 0x354` (move party) and `0x0539 call 0x3e0`
  (terrain-speed messages). Return value `[bp-2]` goes back to the dispatcher:
  `0x0c0f mov [bp-8],ax`, `0x0c30 cmp [bp-8],0 ; jne 0x0c39 ; jmp 0x0d14`. Only the success
  path reaches `0x0c39 mov ax,2 ; push ax ; call 0xffffcdac` = `kernel 0x4f7c`
  `advance_clock(minutes)` (it jumps out at `0x4f84 cmp [bp+4],0` on zero and adds to
  `[0x5881]`). **A blocked step, cactus included, never calls the clock.**
- Also at `0x0c12-0x0c1b`: if transport class != 0x20, `[0x5955]=0`.
- Wind: rolled by the key reader (existing TS/native models), not by this tail.

### 2.3 The helper, `ULTIMA.EXE 0x2AA8` (kernel_party_random_damage), fully read

```
2aa8 push bp / mov bp,sp / sub sp,4 / push di / push si
2ab0 sub si,si              ; i = 0
2ab2 mov di,0x55b3          ; &record[0].status ; di += 0x20 per member
2ab5 mov ax,si ; 2ab7 mov cl,[0x585b] ; 2abb sub ch,ch ; 2abd cmp ax,cx ; 2abf jae 0x2ad6
       ; i < party_size   (UNSIGNED, party_size is a byte at DS 0x585b)
2ac1 cmp byte [di],0x44 ; je 0x2ad6      ; status == 'D'  -> skip: NO draw, NO damage
2ac6 push si                              ; arg1 = member index  (pushed BEFORE the draw)
2ac7 push 1 ; 2acb push 8 ; 2acf call 0x2092   ; rand(1,8)   <-- the only RNG call
2ad2 push ax ; 2ad3 call 0x2a52          ; kernel_apply_damage(member, dmg)  (ret 4)
2ad6 add di,0x20 ; 2ad9 inc si ; 2ada cmp si,6 ; jl 0x2ab5    ; at most 6 slots
2adf mov [bp-2],si ; ... ret
```
`0x2a52` apply_damage(member=[bp+6], dmg=[bp+4]):
```
2a56 push [bp+6] ; 2a59 call 0x2a28        ; invert roster row (XOR; shared with picker/combat)
2a5c push 0xa ; 2a5f push 0x640 ; 2a64 push 0x7d0 ; 2a68 call 0x223c   ; noise_burst, BLOCKING
2a6b push [bp+6] ; 2a6e call 0x2a28        ; un-invert
2a71 si=[bp+6]<<5 ; 2a78 ax=[bp+4]
2a7b sub word [si+0x55b8],ax               ; HP (word) -= dmg   (record+5 from 0x55b3)
2a7f cmp word [si+0x55b8],0 ; 2a84 jg 0x2aa0          ; SIGNED: HP > 0 -> survive
2a86 mov word [si+0x55b8],0 ; 2a8c mov byte [si+0x55b3],0x44   ; HP=0, status='D'
2a91 mov al,[0x587b] ; 2a94 sub ah,ah ; 2a96 cmp [bp+6],ax ; 2a99 jne 0x2aa0
2a9b mov byte [0x587b],0xff                ; dead member was g_active_char -> deselect
2aa0 call 0x2900                           ; full status-panel redraw
2aa5 ret 4
```
- **Draw count:** exactly one `rand(1,8)` per member with `i < party_size`, `i < 6`,
  `status != 'D'`. Nothing else in the reachable call graph draws: I swept every function
  reachable from 0x2aa8 (including graphics leaves reached by non-prologue targets 0x4f3c,
  0xb2d, 0x935, 0x8e6, 0x17f4, 0x1f77, 0xccd, 0xa22, 0x991) with `reach2.py`: the only call to
  `0x2092` is `0x2acf`, and no byte pair `20 54` ([0x5420]) occurs in any of them. The noise
  burst `0x223c` uses a private PRNG at `[0x545c]` (`0x2255-0x2265`), so the sound never moves
  g_rng. The same is true of everything in 0x01FE before the OUCH (0x368e, 0x2c4c, 0x2bd4,
  0x2c2e, 0x1850, 0x1b16 have no draw).
- **Order of draws:** member 0's draw, then member 0's whole 0x2a52 (flash, blip, HP), then
  member 1's draw, and so on. Draws are therefore interleaved with the (blocking) sound, but
  since the sound does not touch g_rng, the *stream* is simply "N consecutive rand(1,8)".
  The draw comes first within each member: `push si` is evaluated, then `rand`, then 0x2a52.
- **Damage target:** all living members, not just the active one. Slot index, not roster
  identity; a slot `>= party_size` is never touched; `party_size` is a byte.
- **Status:** the helper tests only `'D'` (0x44). `'S'` (asleep) and `'P'` (poisoned) members
  take damage and **keep their status**; nothing writes any status except death. There is no
  wake-from-sleep and no poison change anywhere in 0x2aa8/0x2a52.
- **Death:** `HP - dmg <= 0` as a *signed* 16-bit compare (`jg`). `HP == dmg` kills. HP is
  stored as 0 and status `'D'`. If that slot equals `[0x587b]` the active slot becomes 0xff.
  (A stored HP above 0x7fff would behave as negative; unreachable with the game's caps.)
- **SFX:** per damaged member one `noise_burst(step=10, dur=1600, band=2000)` (the existing
  `combat-damage` cue, ~93 ms by the model in `poison_tick.h`), flanked by two XOR flashes of
  that member's roster row. `0x223c` is blocking, so N members = N consecutive blips. Dead
  members produce nothing. No other sound in the cactus branch: the only `beep` in the tail is
  `0x033c`, in the `else`.
- **Redraw:** `0x2900` runs after every member (status panel; calls `0x2726` for slots 0..5).

### 2.4 Text, sound, tick, flush: exact order for a cactus bump (non-sailing vehicle or foot)

1. (frigate only, `(tile&0xfc)==0x24`): `Rowing!` at 0x020e-0x0212, before anything.
2. facing/echo text from `0x0490`/`0x00da` (e.g. `Row ` + `North`), for vehicles.
3. `find_object_at_xy`, passability: no RNG, no text.
4. `Blocked!\n` (0x0322).
5. `OUCH!\n` (0x032f).
6. `0x0336`: N x [rand(1,8) -> flash -> blip -> unflash -> HP -> panel redraw].
7. No beep. `0x0347`: key buffer flush (so keys pressed during the blips are discarded).
8. Return 0: the dispatcher skips `advance_clock` (no minutes, no housekeeping, no world turn).

Non-cactus blocked (control): same 1-4, then `beep(0xa5,0xc8)` (0x033c-0x0344), flush, return 0.

### 2.5 Town is a different routine (control, verified)

`TOWN.OVL 0x083a`: `mov ax,0x26d6` (DS 0x26d6 = `Blocked!\n`) / print / `beep(0xa5,0xc8)` /
`call 0xffff9946` (flush), with no `cmp ...,0x2f` anywhere in that tail. The town tick on a
blocked step is `TOWN 0x15d4 push 1 ; call 0xffffcdac` (1 minute). So cactus-in-town = Blocked
+ beep, no OUCH, no damage (matches `colas-224-acta.md` and `game.ts:1507-1517`).

### 2.6 Where the cacti are (reachability)

Decoded BRIT.DAT with the chunk index at `DATA.OVL 0x3886` (same recipe as
`native/tools/u5pack/cli.ts:70`): 205 chunks, **14 tiles equal to 0x2f**, at (200,19)
(199,22) (206,35) (203,37) (205,38) (203,39) (209,39) (199,41) (217,42) (219,48) (208,49)
(203,51) (227,51) (211,52). All four orthogonal neighbours of every one are desert 0x07
except one west neighbour 0x1c at (205,38). None is water-class (tile < 4 or 0x60-0x6f).
UNDER.DAT: 0 cacti. So no boat can ever stand next to a cactus in unmodified data.

## 8. Unresolved and adjacent findings

**A1. Blocked rowing steps cost no clock in the binary; both ports charge them.** Derived
from the dispatcher (section 2.2): `0x0c30 cmp [bp-8],0 ; jne 0x0c39 ; jmp 0x0d14`, and
`ship_try_move` returns 0 for every blocked outcome (cactus, plain block, collision, dock,
whirlpool). The tick is `0xc39 push 2 ; call 0xffffcdac (-> 0x4f7c advance_clock)`. TS
(`game.ts:1819-1828`: `runNavalTurn` after `resolveNavalStep`) and native
(`commands.cpp:431-432`: `naval_step(dir); naval_turn();`) tick unconditionally, with the HMS
Cape cost model. This is not part of D-89 (the draw, text and SFX order are unaffected) and is
pinned by every blocked naval row of `movement-flow.txt`, so it needs its own adjudication.
What would settle it: a live DOSBox witness of the clock after a blocked skiff step, or
reading `0x0670-0x068c` (the sailing wait-tick) against `0x0c39` for the 0x24/0x28 classes.
The foot side is already correct (minutes 0 outdoors, 1 in town).
