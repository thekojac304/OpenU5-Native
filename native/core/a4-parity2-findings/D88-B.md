# D-88 -- the combat clock (investigation B, lens: ports first)

Scope: READ-ONLY. Nothing in the repository was edited, built or run; the baseline build in
`native/core/build-a4-parity2-baseline` was not touched. Private scratch scripts live in
`.../scratchpad/findings/d88b_work/` (`lib.py` census + base fit, `model.py` executable model of the
quoted instructions, `rep_clear.py`, ...). Every binary claim below was produced by disassembling
`original/u5/ultima5/*` with `re/tools/dis16.py` (capstone, 16-bit) in this session; the notes
(`re/notes/combat.md`, `reloj-advance-clock.md`, `kernel-survival.md`) were read only AFTER the first
disassembly, as a cross-check, and agree with it except where stated.

Address conventions: overlay addresses are FILE offsets of the `.OVL`; kernel addresses are
`ULTIMA.EXE` image offsets after the MZ header (`dis16.py --exe`); DS addresses are the
`DATA.OVL`/DGROUP offsets (DATA.OVL file offset = DS + 0x10).

---

## 1. Verdict

1. The 1988 combat loop (`COMBAT.OVL:0x0b94`) counts **every initiative activation** of a live
   combatant in a **DS global byte `[0x5882]`**. At the 10th activation it zeroes the byte and calls
   **`advance_clock(1)` (kernel `0x4f7c`)** -- the plain minute advance with its calendar/torch/light
   cascade. It does **not** call `turn_housekeeping` (kernel `0x2ae8`); there is no housekeeping,
   no meal, no starvation damage and no poison tick anywhere in combat.
2. The counter is **not combat-local**. It is never initialised on combat entry (the only three
   references to `0x5882` in all 25 binaries (24 `.OVL` incl. DATA.OVL, plus ULTIMA.EXE) are the `inc`, `cmp`, reset at `COMBAT.OVL:0x0c64-0x0c72`);
   it lies inside the 0x1060-byte SAVED.GAM window (`DS:0x55a6..0x6606`) at **file offset `0x2DC`**,
   which is loaded and dumped verbatim. So 9 activations in fight A + 1 in fight B (or across a
   save/load) produce a tick. INIT.GAM and the in-tree reference SAVED.GAM both hold 0 there.
3. The tick happens at the **start** of the 10th activation (before that actor's turn, before any of
   its RNG draws, before the player is prompted), and the counter is reset **before** the clock call.
   The test is `cmp byte [0x5882],0xa / jne` (equality, byte wrap): a loaded value 11..255 does not
   tick until it wraps (255 more activations from 11).
4. Skips: slots with `flags&0xC0==0`, `flags&0x20`, a party member whose roster status is `'D'`
   (killed on the spot, no turn), and a unit standing on tile `0x84/0x85` (never decrements, never
   counts) are NOT counted. Everything else is counted *before* the turn body decides what to do:
   asleep, charmed, dragged-under, fleeing, auto-passed non-active party members, enemies frozen by
   Time Stop / skipped by Quickness, and every turn after "VICTORY!" (combat does not end on victory).
5. In the world, a crossed hour boundary is **never charged by the combat itself**. After combat it
   is **swallowed** on every outdoor, town and ship path I traced (the next `advance_clock(n!=0)`
   re-snapshots `g_prev_hour` before housekeeping looks at it), but it is **charged immediately** after
   a dungeon corridor/room fight (DUNGEON `0x0c76` runs the fight and then housekeeping at `0x0e22` in
   the same step, with no clock call in between). This asymmetry is the main thing a binary-first pass
   misses.
6. Both ports already count activations (`actionCount` in `combat.ts`, `action_count` in
   `combat.h`) at the exactly right point, but the counter is combat-local, unbounded, hashed into
   fixtures, and **wired to nothing**. Neither port advances the clock during combat or at its end.
   The dungeon turn also runs housekeeping BEFORE the fight where the binary runs it AFTER, which
   becomes observable the moment combat ticks exist (section 4/5 item P-3).
7. Tooling warning: the overlay bases in the task brief and in `re/tools/callers_banda.py` are wrong
   for COMBAT (real kernel-call base `0xA290`, not `0xBFEC`), COMSUBS, DUNGEON, INTRO, CAST, BLCKTHRN,
   LOOKOBJ, DNGLOOK, OUTSUBS, SHOPPES3. `callers_banda.py 4f7c` finds 13 of the 21 call sites and
   misses COMBAT's own (section 2.0).

Confidence: high for 1-4, 6, 7 and for the outdoor/town halves of 5; medium-high for the dungeon half
of 5 (code path read, not witnessed in DOSBox). No DOSBox witness was run for anything.

## 2. Binary facts

### 2.0 Method, positive controls, bases

  thunk stubs in `0x7a16-0x7ee0`). Brief value vs fitted value (calls landing on kernel prologues):

|---|---|---|---|
| COMBAT | 210 | 0xBFEC -> 0 | **0xA290 -> 115** (+36 intra-overlay, +45 thunk stubs, 14 false E8 bytes) |
| COMSUBS | 146 | 0x85FE -> 0 | 0xE1E0 -> 82 |
| DUNGEON | 263 | 0xE1E0 -> 0 | 0x81D0 -> 166 |
| INTRO | 614 | 0xCD3A -> 0 | 0x81C0 -> 546 |
| BLCKTHRN | 159 | 0xE63E -> 0 | 0xA290 -> 129 |
| DNGLOOK | 127 | 0xA2B6 -> 0 | 0xA290 -> 104 |
| OUTSUBS | 80 | 0x81D0 -> 0 | 0xA290 -> 68 |
| SHOPPES3 | 124 | 0xA5F6 -> 0 | 0xE1E0 -> 85 |
| CAST | 323 | 0xA8D8 -> 1 | 0xBF80 -> 154 |
| LOOKOBJ | 220 | 0xA444 -> 2 | 0xA290 -> 183 |

| CMDS, SJOG, TALK, MAINOUT, TOWN, SHOPPES | -- | as brief | as brief |

  Cause: `thunks.py --bases` lists "ovl 14 base 0xbfec" -- that is the SJOG stub base (SJOG's own
  kernel-call base is 0xBF80; `0xdaec-0xbf80 = 0x1b6c`, `0xe14e-0xbf80 = 0x21ce`, `0xdfbe-0xbf80 =
  0x203e` match the note's SJOG offsets). It was mislabelled COMBAT. A scratch census by another
  investigator in the shared scratchpad (`census.py`) uses the same corrected table.
* Positive controls: (a) `INTRO.OVL:0x0ec6` resolves with 0x81C0 to kernel `0x256e` (prologue
  `55 8b ec`) and its three pushes are `DS:0x31e6 = "SAVED.GAM"`, `0x55a6`, `0x6606-0x55a6 = 0x1060`;
  (b) `COMBAT.OVL:0x0c76 e8 73 a0` resolves with 0xA290 to kernel `0x4f7c`, whose body starts
  `55 8b ec 83 ec 0a` and takes `ret 2`; with 0xBFEC it lands at `0x6cd8`, mid-function
  (`d6 8a 87 ...`); (c) `byte_sub_saturating` `0x3f36` disassembled and confirmed (`cmp ax,[bp+4]; jbe -> [bx]=0`).

  `re/tools/callers_banda.py 4f7c` prints only 13 sites (ULTIMA.EXE x2, TOWN x3, MAINOUT x6, CMDS x2);
  the 8 it misses: COMBAT `0x0c76`, DUNGEON `0x0f2f`, BLCKTHRN `0x05b4`/`0x0c2e`, CAST2 `0x10f1`,
  OUTSUBS `0x0993`, SHOPPES3 `0x01c1`/`0x01db`.
* Not a DOSBox witness: the timeline numbers in 7.1 come from `model.py`, an executable transcription of
  the quoted instructions, not from running the 1988 game.

### 2.1 The counter and the tick (COMBAT.OVL `0x0b94`, the main loop)

Loop head and skip rules (all verbatim from `dis16.py COMBAT.OVL b94`):

```
0bca  mov byte [0x589e],0            ; slot idx = 0 (g_cmb_actor)
0bcf  mov byte [0x594f],0
0bd4  ... si = 0xba14 + idx*8        ; combatant record (8 B)
0be3  mov al,[si+2]  ; di=ax         ; flags
0be8  test al,0xc0 ; jne 0xbef ; jmp 0xd08      ; SKIP 1: neither player(0x80) nor enemy(0x40) bit
0bef  test al,0x20 ; je 0xbf6  ; jmp 0xd08      ; SKIP 2: dead/cleared
0bf6  test al,0x80 ; je 0xc26                   ; player?
0bfa  bl=[si+3]; bx<<=5 ; cmp byte [bx+0x55b3],0x44 ; jne 0xc26   ; roster status 'D'?
0c0a  or byte [si+2],0x20 ; call kernel 0x3564 ; call 0x1574(idx,0x63) ; jmp 0xd08   ; SKIP 3: finish the dead PC, no turn
0c26  bl=[si+7]; bx<<=5; al=[si+6]; bx+=ax ; al=[bx-0x52ec] (0xAD14+y*32+x) ; and al,0xfe
0c3c  cmp al,0x84 ; jne 0xc43 ; jmp 0xd08       ; SKIP 4: stocks/manacles cell (0x84/0x85), BEFORE the decrement
0c43  dec byte [si+5] ; je 0xc4b ; jmp 0xd08    ; initiative countdown (byte); not zero -> next slot
0c4b  mov al,0x24 ; sub al,[si+1] ; mov [si+5],al      ; reload 36 - speed (byte)
0c53  sub al,al
0c55  mov [0x5898],al ; mov [0x58a2],al ; mov [0x588f],al ; mov [0x5890],al ; mov [0x589d],al   ; AL = 0
0c64  inc byte [0x5882]                         ; <<< THE COUNTER (DS word 0x5882, byte op)
0c68  cmp byte [0x5882],0xa
0c6d  jne 0xc79
0c6f  mov [0x5882],al                           ; AL is still 0 -> counter := 0 (BEFORE the call)
0c72  mov ax,1 ; push ax
0c76  call kernel 0x4f7c                        ; advance_clock(1)  (fitted base 0xA290)
0c79  mov byte [0x589f],1
0c7e  al=[0x589e] ; push ax ; call kernel 0x5646 ; or ax,ax ; je 0xc90
0c8b  call 0x3f4  (enemy/AI/possessed turn)  ; jmp 0xc93
0c90  call 0x63e  (player turn)
0c93  [bx+0x58a8]=0xff ; call 0x1b1e (hazard cell damage) ; call thunk 0x7e8a (SJOG 0x1b6c: recount) 
0ca9  ... exit tests (2.8)
0d08  inc byte [0x589e] ; cmp byte [0x589e],0x20 ; jae 0xcc1 ; jmp 0xbcf
0d16  cmp word [bp-8],0 ; jne 0xd1f ; jmp 0xbca      ; next full pass of the 32 slots
```

Reading: the increment happens exactly once per *activation* (the slot's countdown reached zero),
after skips 1-4, before the AI/player dispatch at `0x0c84-0x0c90`, and therefore before the turn body
(`0x03f4`, `0x063e`) decides anything. The decrement test is a byte `dec`; initiative counters wrap
(`0x24 - [si+1]` is a byte subtraction).

### 2.2 Storage, persistence, initialisation of `[0x5882]`

* Census of the operand word `82 58` in all 24 `.OVL` files (DATA.OVL and FLAMES.OVL included) and `ULTIMA.EXE` finds exactly three
  hits, `COMBAT.OVL:0x0c66`, `0x0c6a`, `0x0c70` (inc / cmp / reset). No other direct reference; none in
  the kernel. Indexed accesses with a base below it were checked for the neighbours `0x587f/0x5880/0x5881`
  (all direct `a0/a2/80 3e` forms, none indexed). A scan of every `rep stos/movs` preceded by `mov di,imm`
  with `imm` in the state window found no bulk operation covering `0x5882` (`d88b_work/rep_clear.py`).
* The state window is loaded and saved as one block: load `INTRO.OVL:0x0eb4` (`push 0x31e6 "SAVED.GAM";
  push 0x55a6; push 0x6606-0x55a6 = 0x1060; push 0; call kernel 0x256e`); writers
  `CAST2.OVL:0x1194` (`call 0x43f8 -> kernel 0x25d8` with `0x9698 "SAVED.GAM"`, `0x55a6`, `0x1060`),
  `INTRO.OVL:0x1e08` (name `0x364b`), `FONT.OVL:0x0e3d` (name `0xa0d6`); all four names read
  `"SAVED.GAM"`. `0x5882 - 0x55a6 = 0x2DC < 0x1060`, so the counter is saved and restored.
* Neighbours confirm the offset: `g_year 0x5874 -> 0x2CE`, `g_hour 0x587f -> 0x2D9`, `g_prev_hour
  0x5880 -> 0x2DA`, `g_minute 0x5881 -> 0x2DB`, **`0x5882 -> 0x2DC`**, `g_wind_drift 0x5883 -> 0x2DD`.
* Values in the tree: `INIT.GAM[0x2d9..0x2de] = 08 00 23 00 00 00`, `SAVED.GAM[0x2d9..0x2de] = 03 03 27 00 00 00`
  (hour/prev_hour/minute/**counter**/drift/...): both counters are 0. No in-tree save has a non-zero
  counter, so persistence rests on the code, not on a witness (section 8).

### 2.3 What counts (and what does not)

Counted (the increment at `0x0c64` is unconditional once past skips 1-4):

| situation | evidence |
|---|---|
| any player or enemy activation, whatever it then does (move, attack, pass, cast, flee, fail a key) | the turn bodies are entered after `0x0c64`; one activation = one count regardless of keystrokes inside `0x063e` |
| asleep enemy (flag 0x08) whose AI turn then mostly skips | `0x03f4` tests `flags&8` at `0x0446` long after the count |
| enemy under Time Stop ('T', `0x587a==0x54`) -> `jmp 0x540` | `0x0418-0x041f` |
| Quickness ('Q') skipping the enemy turn on `rand(0,1)==0` | `0x0422-0x0437` |
| dragged-under (flag 4) -> `jmp 0x540` | `0x043d-0x0443` |
| non-active party member auto-passed (`g_active_char != own slot`, `call 0xffffda86`, `jmp 0xb8e`) | `0x063e: 0x0666-0x067f` -- after the tick |
| chaos-sword possessed member (switched to `0x03f4`) | `0x0691-0x06c1` |
| every turn after "VICTORY!" until the party has left | 2.8 |

Not counted: SKIP 1-4 above. In particular a unit on a `0x84/0x85` cell never decrements, so it never
acts and never counts. Only four cells in the shipped maps have those tiles: `DUNGEON.CBT[38]` (6,1),(7,1)
and `DUNGEON.CBT[40]` (7,2),(8,2); `DUNGEON.CBT[40]` map-unit 0 (raw sprite `0x50`) starts on (8,2)
(`d88b_work`, parsed with the extractor layout: rows 5-7 = sprite/x/y of 16 map units). Neither port
models this skip (5/4 item N-5).

### 2.4 What `advance_clock(1)` does (kernel `0x4f7c`, bytes `0x4f7c-0x519c`)

```
4f84 cmp word [bp+4],0 ; 4f88 jne 0x4f8d ; 4f8a jmp 0x50a1       ; delta==0 -> TAIL only (no snapshot)
4f8d cmp byte [0x587a],0x51 ; jne ; sar word [bp+4],1 ; if 0 then inc -> 1      ; 'Q': 1>>1=0 -> forced back to 1
4fa0 mov al,[0x587f] ; mov [0x5880],al                           ; g_prev_hour := g_hour   (BEFORE the 'T' test)
4fa6 cmp byte [0x587a],0x54 ; je 0x4fc8                          ; 'T': skip the add AND both torch/light subtracts
4fb0 add byte [0x5881],al                                        ; minute += delta (byte)
4fb4 call 0x3f36(&[0x58a7], delta) ; 4fbe call 0x3f36(&[0x58a6], delta)   ; torch / light spell: 0 if <= delta, else -= delta
4fc8 cmp byte [0x5881],0x3b ; ja ; sub byte [0x5881],0x3c
4fd7 call 0x3f36(&[0x588c],1) ; 4fe2 inc byte [0x587f]           ; hour++ (and the 0x588c healing cooldown -1)
4fe6 cmp byte [0x587f],0x17 ; ja -> [0x587f]=0, MIDNIGHT block 0x4ff5-0x504f, day++ (0x5051 ...)
50a1 light level recompute (always, also for delta 0) ; 514a: if g_hour != [0x5880]: (location<0x21 && floor<0x80 -> call 0x4a84 sky strip) ; 12-hour clock [0x5884]
5186 if 0 < [0x5893] < 0x21: call 0x71aa  ; 519c ret 2
```

Midnight block (executed only when hour wraps 23 -> 0): for slot i = 0..2: skip if `byte[0x58c8+i] >= 0x80`;
else loop `rand_range(1,8)` (`push 1; push 8; call 0x2092` at `0x5004-0x500c`); candidate is zeroed if it equals
`[0x5893]` (`0x5011-0x501a`) or any of the three slot bytes including the slot's own old value
(`0x501c-0x502d`); `or di,di / je 0x5004` re-draws without bound. At least 3 draws, no upper bound.

Month block: day `> 0x1c` -> `[0x585a]=[0x5859]=[0x5858]=[0x57b2]=0`, day=1, `[0x5959]=0`, months-at-inn +1
(cap `0x19`, `jae`) for the 16 roster rows, month `> 0xd` -> month=1, `inc word [0x5874]`.

So for the combat call (`delta = 1`): minute+1 (carry cascades), torch-1, light-spell-1 (both saturating),
`g_prev_hour := g_hour` before the add, 0x588c -1 per hour, midnight RNG, day/month/year. It does not touch
food, party HP/status, `g_turn_count (0x588b)` or `g_time_spell_turns (0x588e)` (those are housekeeping).

### 2.5 `g_location = 0xFF` for the whole arena

`ULTIMA.EXE:0x5f86` (the combat starter) does `5fa8 mov al,[0x5893]; 5fab mov [0x5894],al` ... `5fb4
mov byte [0x5893],0xff` before `6069 call 0xe49` and restores `6091 mov al,[0x5894]; 6094 mov [0x5893],al`.
`DUNGEON.OVL` does the same around its direct combat call (`0x007e-0x0081` save, `0x00a8` set `0xff`,
`0x00d5-0x00d8`/`0x0106-0x0109` restore). Consequences inside the combat tick:

* the tail's `cmp [0x5893],0x21 ; jae` (`0x5153`) skips `draw_sky_strip 0x4a84` -> **no moon-phase latch refresh**
  during combat; `0x5186-0x518d` skips `clock_driver_notify 0x71aa`;
* the Shadowlord exclusion at `0x5011` compares against `0xFF`, so **no town-location exclusion**
  (outdoors and in dungeons the world location also never equals 1..8; only fights in towns with
  `g_location in 1..8` differ from what the ports would compute, section 5 item N-4).

### 2.6 Housekeeping (kernel `0x2ae8`) and the only two `g_prev_hour` writers

```
2b5d mov al,[0x5880] ; 2b60 cmp [0x587f],al ; je 0x2b9f                   ; hour changed since the snapshot?
2b66 cmp word [0x57a8],0 ; jne 0x2b7a ; push 0x54c8 "Starving!\n" ; call 0x1850 ; call 0x2aa8 (rand(1,8) per live member) ; jmp 0x2b99
2b7a hour in {6,12,0x12} -> push &[0x57a8] ; push eaters ; call 0x3f54 (word saturating sub)
2b99 mov al,[0x587f] ; mov [0x5880],al                                      ; prev_hour := hour  (consumes the edge)
2b9f turn counter (byte, saturating at 0xff) ; 2bae time-spell turns dec ; 2bca call 0x400c (ring regen) ; ret
```

The poison tick (`'P'` -> `0x2a52(i,1)`, `0x2b36-0x2b40`) and the eaters count (`status != 'D' && != 'S'`) are
in the same function. `g_prev_hour` (DS `0x5880`) has exactly **two writers** in all binaries: `ULTIMA.EXE:0x2b9d`
(housekeeping) and `0x4fa4` (the snapshot inside `advance_clock`). Hence: a tick that crosses an hour leaves
`hour != prev_hour` until (a) housekeeping consumes it, or (b) another `advance_clock(n != 0)` overwrites
the snapshot with the *new* hour -- which silently discards the edge.

### 2.7 Per-context order of clock vs fight vs housekeeping (where the swallow comes from)

| context | order in one consumed turn | verbatim |
|---|---|---|
| Outdoors (`MAINOUT.OVL` loop `0x0a84`) | command -> `advance_clock(2)` -> terrain checks -> `call 0xa60` -> **housekeeping** -> ... -> actor loop `0x1a60` (monster-initiated fights start here, via `0x1ac9 call 0x131a -> 0x1399 call 0x1248 -> 0x1310 call 0x6150`) | `0x0c0f mov [bp-8],ax` (turn flag); `0x0c30 cmp [bp-8],0 ; jne 0xc39 ; jmp 0xd14`; `0x0c39 mov ax,2 ; push ; 0x0c3d call advance_clock`; `0x0cd0 call 0xa60 ; 0x0cd3 call kernel 0x2ae8`; `0x0d11 call 0x1a60` |
| Outdoors, (A)ttack | `0x3178` dispatcher `0x41` -> thunk `0x7bae` -> `MAINOUT:0x06ec` ("Attack-", DS `0x29fe`) -> `0x0778 push [0x5876] ; 0x077c call kernel 0x6150`; the routine returns `[bp-2] = 0` (set `0x06f2`, never changed) -> turn flag 0 -> **no advance_clock(2), no housekeeping, no actors** for that iteration | `0x0789 mov ax,[bp-2]` |
| Town (`TOWN.OVL` loop `0x141e`) | command -> save hour -> `advance_clock(1)` -> hour 5/20 check (`0x15c8-0x15e9 -> call 0x170`) -> `call 0xf02` (post-move effects, ends in **housekeeping `0x10d0`**) -> guard/NPC phases (`0x165f`, `0x166e`) | `0x15d0 mov ax,1 ; push ; 0x15d4 call advance_clock` ; `0x15ec call 0xf02` |
| Town fight return | `TOWN:0x09bc`: `call 0x52 ; push [bx+0x5f6a] ; 0x09d0 call kernel 0x6150 ; call 0xb0 ; push 0 ; 0x09dc call 0x408` (floor reload; `0x04fa-0x0508` night check -> `call 0x170`; **`0x050e sub ax,ax ; push ax ; 0x0511 call advance_clock` = delta 0**) | |
| `ULTIMA.EXE:0x6150` (overworld/town fight starter) after combat | `0x6347 call 0x5f86 ; 0x634d call kernel 0x8016 (-> SJOG 0x203e cleanup) ; 0x6350 call 0x5e4a ; 0x6353 sub ax,ax ; push ax ; 0x6356 call advance_clock` = **delta 0: light recompute + tail only (sky strip + moon latch + 12 h clock), NO snapshot, NO housekeeping** | |
| Dungeon (`DUNGEON.OVL` fn `0x0e2e`) | command -> **`advance_clock(1)` at `0x0f2f`** (normal step: `0x0fea mov di,1 ; mov ax,di ; jmp 0xf2e -> push ax`; 'Q': every other step via `0x0f25 xor di,1`; 'T': none via `0x0f34 sub di,di`) -> `0x0f84 call 0xc76` -> inside `0xc76`: sleeper wake loop, wanderer `call 0x7e2`, **corridor fight `0x0ceb call 0xb7e` (-> `0x0c53 call 0x5f86`, flags 2)**, **room fight `0x0d40 call 0x0`** -> common tail `0x0e1f call 0x2900 ; 0x0e22 call kernel 0x2ae8` | housekeeping comes AFTER the fights |

Therefore after an in-combat crossing:

* outdoors/towns/ships: `hour != prev_hour` survives the delta-0 calls (`0x6356`, TOWN `0x0511`), and the
  next *consumed* turn's `advance_clock(2|1)` overwrites `prev_hour` with the new hour before housekeeping
  runs -> meal and starvation of that crossing are **lost** (food unchanged, no "Starving!", no damage);
* dungeon fight steps: housekeeping `0x0e22` follows the fight directly -> the crossing is **charged
  immediately**, unless a combat tick re-snapshotted `prev_hour` after the *step's own* crossing (then
  the step's own crossing is swallowed instead). Steps under 'T' (and the odd steps under 'Q') call no
  `advance_clock`, so a pending crossing is also charged by the next housekeeping there.

### 2.8 Exit of the loop; combat does not end on victory

```
0ca6 call thunk 0x7e8a (SJOG 0x1b6c: recount -> [0x5876]=live enemies, [0x5878]=live players)
0ca9 cmp [0x5878],0 ; jne 0xce8                 ; players alive
0cb0 cmp [0x5876],0 ; jne 0xcca                 ; both zero -> [bp-2]=0, exit (0xcb7-0xcc7 -> 0xd16 -> 0xd1f)
0cca call thunk 0x7e7e (SJOG 0x21ce: charmed-member "passes out", returns slot or -1) ; inc ax ; jne 0xd08
0cd3 cmp [0x58a3],0 ; jne 0xcbc ; push 0x6eee "\nBATTLE IS LOST!" ; call 0x75c0 ; [bp-2]=1 ; jmp 0xcbc (exit)
0ce8 cmp [0x5876],0 ; jne 0xd08                 ; players alive and enemies gone:
0cef cmp [0x58a3],0 ; jne 0xd08 ; push 0x6f00 "\nVICTORY!\n" ; call 0x75c0 ; [0x58a3]=1 ; call 0xa0d8 ; call 0x7886 -> falls to 0xd08 (CONTINUE the loop)
0d1f call kernel 0x1b16 ; mov byte [0x2186],0xff ; mov ax,[bp-2] ; ret
```

The loop exits only when the party side is empty. After victory the party keeps taking turns (all counted,
all able to tick) until each member leaves by the edge or dies. A fight "ends" after the activation whose turn
empties the side; the tick of that activation (if it was the 10th) has already happened.

### 2.9 Time spells inside the tick and in the turn bodies

* 'Q' (`0x51`): `advance_clock(1)`: `sar` gives 0, forced to 1 (`0x4f94-0x4f9d`) -> no halving at n=1.
* 'T' (`0x54`): the tick performs only `prev_hour := hour` (`0x4fa0`) and the saturating-free path to
  the tail; minute/torch/light unchanged. It also silently discards a pending crossing.
* Enemy turn bodies are unaffected by the counter: 'T' -> `jmp 0x540` (turn lost), 'Q' -> 50 % lost.

### 2.10 Ordering of RNG, text, sound, clock

Within one activation: tick (`0x0c64-0x0c76`, RNG only at midnight: >= 3 `rand_range(1,8)`) ->
`0x589f := 1` -> side classifier `0x5646` -> turn body (AI / player prompt, all its draws, text and sound).
The tick emits no text and no sound (`0x2900` status redraw only on a day rollover, `0x509e`).
The RNG is the single kernel stream (`0x2092`); the ports fork it per arena and write it back
(`finalSeed` / `world.game.rng.seed(state.rng.get_seed())`), so tick draws must come from the arena's own
stream at that point.

### 2.11 Other facts that bound the fix

* No housekeeping, no `apply_damage 0x2a52`, no `party_random_damage 0x2aa8` call exists in COMBAT.OVL
  (full call map in `d88b_work/callmap.py`): poison/starvation/meals never happen during a fight.
  Hazard cells (`0x1b1e`: tiles 0x8f/0xbc fire, 4 swamp, fields 0xea/0xe8/0xe9) are separate.
* `g_turn_count 0x588b` and `g_time_spell_turns 0x588e` change only in housekeeping.
* `COMBAT.OVL:0x0b94` has no intra-overlay caller; it is entered only through thunk `0x7c32`
  (section 3). No raw word reference (function pointer) to `0x0e49`, `0x7c32`, `0x5f86`, `0x6150` exists.
