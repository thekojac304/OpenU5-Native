# D-86 (B, ports-first lens): the dungeon digit key naming an invalid member

Investigator B. Read-only; nothing in the repository was touched. Scratch scripts live in
`scratchpad/findings/d86b/` (other investigators share the parent folder and overwrite
generically named files there, so only `d86b/*` and this report are mine).

All addresses below were disassembled in this session with `re/tools/dis16.py` (capstone,
16-bit). Notation: `OVL:0xXXXX` is a FILE offset in the overlay (the notes' CS:IP for
overlays); `K:0xXXXX` is a ULTIMA.EXE offset read with `--exe`; `DS 0xXXXX` is a DATA.OVL
offset (file offset = DS + 0x10).

---------------------------------------------------------------------------------------

## 1 Verdict

1. **The previously identified path is right, but it does less than the ledger says.**
   `DUNGEON.OVL:0x07c8-0x07d1` calls the shared kernel set-active routine (K:0x4080), stores
   its return value, and then **overwrites it with 0** (`mov [bp-2],0` at 0x07d1). That
   return value is the dungeon loop's "a turn passed" flag (`si`). So for EVERY digit key
   (valid, `0`, invalid) the dungeon loop **skips its post-turn chain** (`call 0x0c76`:
   sleeper-wake rolls, cell events, status redraw, `kernel_turn_housekeeping` K:0x2ae8). The
   kernel itself returns **1 only for the invalid case**; the overlay discards that 1.
   Overworld (`MAINOUT.OVL:0x0c0c`) and town (`TOWN.OVL:0x0ef3`) do NOT discard it: an
   invalid digit there passes a turn. Only the dungeon forces "no turn".
2. **Text for the invalid case**: `"Set Active Plr:\n"` (DS 0xa396, K:0x4095-0x4099) then
   `"Invalid!\n"` (DS 0xa3b0, K:0x40f0-0x40f4). No sound, no RNG draw, no redraw call, no state
   write on the invalid path.
3. **The stray tick arrives in native, and in a much smaller form in the TypeScript
   reference** (both keyed on `position.location === 0`, which is true inside a dungeon
   because both ports leave the surface position in place):
   - native `commands.cpp:781` `if(!g.position.map.location)r.turn();` runs the full
     OUTDOOR turn (`Runner::turn`, `commands.cpp:199-247`): wind roll, 2 minutes of clock,
     housekeeping, door/actor ticks, outdoor spawn roll and world turn. Large.
   - reference `game.ts:2187` `if (this.state.position.location === 0) runContextTurn(...)`
     reaches `runContextTurn`'s DUNGEON tail (`game.ts:2651-2653`, because
     `effectiveLocation` is 0x21..0x28): `tickDoorsAndNpcs()` + `checkRefuge()`. No clock, no
     RNG, no housekeeping. Small, but it is still a stray call the binary does not make
     for that key. The ledger/ALPHA4_UI classify D-86 as "native" only; the reference has a
     residual.
4. **Smallest routing change** (section 7): native `commands.cpp:781` add `&&!c.dungeon`
   (same discriminator the Ignite arm already uses at `commands.cpp:789`); reference
   `game.ts:2187` add `&& !this.dungeonState`. Outcome: the invalid digit prints
   `Invalid!`, changes nothing, draws nothing, in a dungeon only.
5. **Surprise the implementer must decide on (binary-proven, not yet run)**: the
   dungeon loop's clock tick (`advance_clock(1)`, K:0x4f7c via `DUNGEON.OVL:0x0f2f`) is
   executed **once per loop iteration, before the key is read, whatever the previous key
   was**. It is NOT gated on the handler's return value (see section 2.C). So in the
   1988 binary a digit key (and every other "no turn" dungeon key: Z, R, N, P, A...) still
   costs the 1-minute clock tick; only the post-turn chain (wake rolls, events,
   housekeeping) is skipped. Both ports bundle clock+housekeeping into one "turn" and
   charge nothing for return-0 keys. The minimal D-86 fix (remove the stray overworld turn)
   leaves that pre-existing, key-independent divergence untouched; the binary-exact
   variant is a wider, separate change (section 7.4). `re/notes/dungeon.md` §1 and
   `survival.ts` line 77 read `[bp-0xe]` as "the dispatcher's return"; it is the party
   state from `0x39fc` (section 2.C).

Confidence: high on the digit routing, strings, return values, widths and RNG absence
(each read in this session); high (static proof, two independent reads of every write to
the relevant locals) on the loop-top tick; medium-high on the exact count of stray native
effects (read from source, not run: no build/ctest allowed).

## 2 Binary facts

### A. Tooling controls (before trusting anything)

- **Base table error that matters for this very item.** `re/tools/callers_banda.py`
  (and the task brief) use base `0xE1E0` for `DUNGEON.OVL`. Wrong. I scored every
  `E8 rel16` in each overlay whose flat target lies outside the file, under every candidate
  base, by how many land on a `55 8B EC` kernel prologue:
  `DUNGEON.OVL`: base `0x81D0` -> 166 of 190; base `0xE1E0` -> **0** of 146; `0x8304` -> 0.
  (Script: `d86b/` basecheck output below; the same stat shows `MAINOUT 0x81D0` 182/204,
  `TOWN 0x81D0` 144/158, `CAST2 0xE1E0` 183/195.) With the table's `0xE1E0` the by-band
  census **misses every DUNGEON.OVL kernel call**: `callers_banda.py 0x4080` prints only
  `TOWN 0x0ef3` and `MAINOUT 0x0c0c` and omits `DUNGEON 0x07cb`; `callers_banda.py 0x3178`
  omits `DUNGEON 0x07a3`. The old note (`dungeon-dispatch-gates.md` §1) used 0x81D0
  correctly. Other overlays also disagree with the table in the same scoring (BLCKTHRN, COMBAT,
  OUTSUBS best at 0xA290; CAST, TALK at 0xBF80; SHOPPES2/3, ZSTATS, COMSUBS at 0xE1E0) --
  not D-86's concern, but a census with the table can silently miss callers.
- **Positive controls passed**: `DUNGEON.OVL:0x07a3 call 0xffffafa8` -> (0xafa8+0x81d0)&0xffff
  = 0x3178 = a `55 8B EC` prologue (`cmp ax,0x4d` dispatcher); `OVL:0x07cb call 0xffffbeb0`
  -> 0x4080 whose strings read `DS 0xa396 = "Set Active Plr:\n"` (DS+0x10 rule verified
  byte for byte: `0xa3a8 "None!\n"`, `0xa3b0 "Invalid!\n"`, `0x2d0b "Turn around.\n"`,
  `0x2d2d "Exit to DOS? "`); `K:0x2092` is the LCG (`ror ax,1 x3`, `xor 0x9248`, `add 0x11`,
  `div (hi-lo+1)`, `ret 4`) and `DUNGEON 0x0caf call 0xffff9ec2` -> 0x2092 with args
  `(0,0x3f)`.

### B. The dispatcher: `DUNGEON.OVL:0x06c4` (key handler, `ret 2`, returns `[bp-2]`)

```
06c4 push bp / mov bp,sp / sub sp,4 / push si
06cb mov word [bp-2],1                     ; return value defaults to 1 = "turn"
06d0 mov ax,[bp+4]                         ; the cooked key
06d3 cmp ax,0xb / je 0x6f2 / jle 0x6dd / jmp 0x7a8
06dd cmp ax,1 / jge 0x6e5 / jmp 0x7bc      ; key<1 -> digit gate
06e5 cmp ax,4 / jle 0x744                  ; 1..4 arrows -> move (0x0502)
06ea cmp ax,5 / je 0x710                   ; 5 -> Exit-to-DOS-style prompt
06ef jmp 0x7bc
07a8 cmp ax,0x0d/je 0x744; 0x13/je 0x776; 0x16/je 0x73a; 0x2e/je 0x744  ; ENTER . ^S ^V
07bc cmp word [bp+4],0x30 / jb 0x7a0       ; < '0' -> kernel dispatcher
07c2 cmp word [bp+4],0x39 / ja 0x7a0       ; > '9' -> kernel dispatcher
07c8 push word [bp+4]                      ; ff 76 04
07cb call 0xffffbeb0   -> K:0x4080         ; e8 e2 b6
07ce mov [bp-2],ax                         ; 89 46 fe   (kernel's return, stored...)
07d1 mov word [bp-2],0                     ; c7 46 fe 00 00   (...and overwritten)
07d6 jmp 0x70a -> 0x7da: pop si / mov sp,bp / pop bp / ret 2
07a0 push word [bp+4] / call 0xffffafa8 -> K:0x3178 / jmp 0x771 (return = kernel's value)
```
Raw bytes dumped: `0x07c8..0x07d8 = ff7604 e8e2b6 8946fe c746fe0000 e931ff`;
`0x07a0 = ff7604 e802a8 ebc9`. Widths: the key is a 16-bit word, compares are unsigned
(`jb`/`ja`); the return is a 16-bit word. Digit gate is exactly `0x30 <= key <= 0x39`.
Digit `'0'` (0x30) is a digit; key code 0x0000 or 0x0001..0x0005 are NOT (they take the
earlier branches).

### C. The kernel routine: `K:0x4080` (return `[bp-2]`, `ret 2`)

```
4087 mov word [bp-2],1                     ; return = 1 unless overwritten with 0
408c mov ax,[bp+4] ; sub ax,0x31 ; mov [bp-4],ax      ; idx = key-'1' (16-bit)
4095 mov ax,0xa396 / push / call 0x1850    ; prints DS 0xa396 "Set Active Plr:\n"
409c cmp word [bp+4],0x30 / jne 0x40b8
40a2 push 0xa3a8 / call 0x1850             ; "None!\n"
40a9 mov byte [0x587b],0xff                ; g_active_char = none
40ae call 0x2900                           ; status redraw
40b1 mov word [bp-2],0 / jmp 0x40f7        ; return 0
40b8 mov al,[0x585b] ; sub ah,ah ; cmp [bp-4],ax ; jae 0x40f0   ; idx >= party_size (UNSIGNED word vs zero-extended byte)
40c2 si = idx<<5 ; cmp byte [si+0x55b3],0x44 /je 0x40f0 ; cmp byte [si+0x55b3],0x53 /je 0x40f0
40d7 mov al,[bp-4] ; mov [0x587b],al       ; g_active_char = idx
40dd lea ax,[si+0x55a8] ; push ; call 0x1850        ; prints the NAME (roster record +0) ...
40e6 push 0xa ; call 0x16ba                         ; ... then '\n'
40ed jmp 0x40ae                                      ; call 0x2900, return 0
40f0 push 0xa3b0 ; call 0x1850             ; "Invalid!\n"  (return stays 1, NO 0x2900, NO state write)
40f7 mov ax,[bp-2] ... ret 2
```
Outcomes (kernel level): digit `0` -> `None!`, active=0xFF, redraw, **returns 0**; digit
`1..9` with `idx < [0x585b]` and status byte (record+0xB at 0x55b3+idx*0x20) not `'D'`
(0x44) and not `'S'` (0x53) -> name + newline, active=idx, redraw, **returns 0**;
anything else -> `"Invalid!\n"`, **returns 1**. Consequences:
- Status `'P'` (poisoned), `'G'` and any other byte are VALID; only `D` and `S` refuse.
- Digits beyond the party size (e.g. `7`,`8`,`9`, which give idx 6..8 >= 6 >= party_size
  ever possible) are invalid; an inn companion beyond `party_size` is invalid even if alive.
  No check against 6; the bound is purely the byte at 0x585b.
- Reachable callees of 0x4080 (call-graph walk, bodies delimited by the next `55 8B EC`):
  `0x1850` print string, `0x16ba` putchar, `0x2900` status redraw and their subtrees. **No
  call to the RNG `0x2092` anywhere in that closure** (checked; 0x4f3c, 0x17f4, 0x1f77 are
  non-prologue entries, disassembled by hand: no rand). RNG draws = 0 for every digit
  outcome. Caveat: bodies were delimited by prologues, not by `ret`, so this is a
  strong static result, not a symbolic proof.

### D. The dungeon loop that consumes the return value (`DUNGEON.OVL:0x0e2e`, `ret 2`)

Per-iteration order, with every write of the relevant locals checked (`[bp-0xe]` is written
only at 0x0e3b `=0` and 0x0fab `=ax`; byte dump confirms no other writer):

```
0f93 cmp [bp-0xc],0 / je 0xff2                    ; loop head: exit when flag cleared
0f99 cmp byte [0x5893],0x20 / jbe 0xff2           ; left the dungeon (g_location<=0x20) -> exit
0fa0 mov [bp-0xc],1 ; mov si,1                    ; si = "turn passed" default 1
0fa8 call 0xffffb82c -> K:0x39fc                  ; party_conscious_state: 0 if any 'G'/'P'
0fab mov [bp-0xe],ax                              ;   1 if none but some 'S', -1 if neither
0fae..0fd0 (ax==1: "\n" + 0x4c2a + DS 0x2ddd string; ax<0: flag=0,si=0 ; ax!=0 -> jmp 0xf93)
0fd6 cmp byte [0x587a],0x54 / je 0xf1e            ; 'T' time stop
0fe0 cmp byte [0x587a],0x51 / je 0xf1e            ; 'Q' quickness
0fea mov di,1 ; mov ax,di ; jmp 0xf2e             ; bytes e9 3c ff at 0xfef  -> 0xf2e
0f1e (T/Q): cmp [0x587a],0x51 / jne 0xf34 ; xor di,1 / je 0xf36 ; mov ax,1
0f2e push ax ; 0f2f call 0xffffcdac -> K:0x4f7c   ; advance_clock(1)   <-- THE CLOCK TICK
0f34 sub di,di (T: no tick) ; 0f36 call 0x03d6    ; blocking getkey wrapper (returns key != 0)
0f39 mov [bp-8],ax ; cmp ax,0xffff ; jle 0xf47
0f41 push ax ; 0f42 call 0x06c4 ; 0f45 mov si,ax  ; si = handler return (the ONLY caller of 0x06c4)
0f47 cmp byte [0x5893],0x21 / jae 0xf53 (else si=0,[bp-0xc]=0)
0f53..0f78  read tile under party -> [bp-2]
0f7b or si,si / je 0xf87                          ; si==0 : post-turn chain SKIPPED
0f7f mov al,[bp-2] ; push ax ; push di ; call 0x0c76   ; post-turn chain (the only caller)
0f87 ... falls into 0xf93 (next iteration)
```
Facts that fall out:
1. **`si` (= 0x06c4's return) gates exactly one thing: the call to `0x0c76`** (post-turn
   chain, only caller 0x0f84). `0x0c76` = for each member `'S'` roll `rand(0,0x3f)<4` -> wake
   (`0x0caf call 0x2092`, args `(0,0x3f)`), `call 0x07e2` when `di!=0` (cell events), field/trap
   handling, then the common tail `0x0e1f call 0xa730`(K:0x2900 redraw) and `0x0e22 call 0xa918`
   (K:0x2ae8 `kernel_turn_housekeeping`: poison loop, hunger/meal block on an hour change
   `[0x587f]!=[0x5880]`, turn counter, time-spell countdown, ring regen K:0x400c).
2. **The clock tick `K:0x4f7c(1)` at 0x0f2f is NOT gated on `si`.** It sits between the
   loop-head gate and the getkey, so it runs once per iteration, i.e. once per key, after the
   previous key was fully handled, for every key and every return value. The only
   conditions on it are the head gate result `[bp-0xe]==0`, `'T'` (never ticks),
   `'Q'` (ticks every second iteration via `xor di,1`). `re/notes/dungeon.md` §1 reads
   `[bp-0xe]` as "the dispatcher returned 0": it is `0x39fc`, set at 0x0fab BEFORE the key.
   The census of kernel callers of `0x4f7c` finds exactly one in `DUNGEON.OVL` (0x0f2f).
3. `K:0x4f7c`: `[bp+4]==0` returns; `'Q'` halves (`sar`, min 1); `[0x5880]=[0x587f]` (previous
   hour) is copied on EVERY call (0x4fa0-0x4fa3); `'T'` skips the add; adds the minutes to
   `[0x5881]`, carries at >0x3b into the hour `[0x587f]`; midnight (`>0x17`) runs the
   Shadowlord re-roll with `rand(1,8)` (0x500c). A no-turn key between a tick and the next
   tick therefore swallows a one-time hour-boundary meal/starvation check (the next tick
   resets `[0x5880]` before housekeeping ever compares).
4. The blocking getkey `0x03d6` (loops until a non-zero key; `0x1b38` poll, `0x2032` =
   toupper) contains no RNG in its closure (walked). Digits are plain ASCII 0x30-0x39
   (`toupper` is the identity on them); keys 1-4 get `+0xfa` when `[0x538a]==0` (arrows;
   not relevant to digits).

Result for a dungeon digit key, in order: `K:0x4080` prints and (valid/None) redraws,
the overlay returns 0, no `0x0c76`, no housekeeping, **no RNG**, then the next iteration's
head gate and its `advance_clock(1)` (unless `'T'`; every second time under `'Q'`) before
the next getkey.

### E. Overworld and town for contrast (so the fix stays dungeon-only)

- **Overworld `MAINOUT.OVL:0x0c06-0x0c3d`**: `call 0xffffbeb0` (K:0x4080) -> `[bp-8]=ax`;
  `0x0c30 cmp [bp-8],0 / jne 0x0c39` -> `0x0c39 push 2 / call 0xffffcdac` = advance_clock(2).
  So an invalid digit above ground passes a full overworld turn (native/TS do this).
- **Town `TOWN.OVL:0x0ef0-0x0ef9`** (handler 0x0e34, harpsichord intercept first) returns
  K:0x4080's value; the town loop (`0x159a mov [bp-0xa],ax`, `cmp [bp-0xa],0 / jne`, `0x15d4
  push 1 / call 0xffffcdac`, `0x15ec call 0x0f02`) therefore **also passes a town turn for an
  invalid digit** (clock(1) + post-turn + NPC ticks). Native `commands.cpp:781` and the
  reference `game.ts:2187` give a town NO turn (the reference docblock at `game.ts:2160-2170`
  says "no derivado"; `game/tests/game.test.ts:449-497` pins "pueblo: Invalid no corre
  world_turn"). That is a separate, adjacent divergence (not D-86): do not "fix" it by
  accident.
