# D-89 (A4-PARITY2) — the naval / cactus "OUCH!" routine — investigator A (binary first)

Method: I disassembled and derived the whole routine BEFORE opening any re/notes file, any TypeScript or any C++.
Only afterwards did I compare. Everything in section 2 and 3 is from `original/u5/ultima5/*` read in this session
with `capstone` (16-bit) via `re/tools/dis16.py`-equivalent scratch scripts (`d.py`, `census_ds.py`, `d89a_show.py`,
`d89a_mf.ts` in the findings folder) and `re/tools/callers_banda.py`. The scratch folder is shared with other
investigators: some files there (`show.py`, `mf_cactus.ts`) are theirs; I did not rely on them.

Conventions: `K:xxxx` = ULTIMA.EXE kernel offset (MZ header stripped, `--exe`); `MO:xxxx` = MAINOUT.OVL file offset
(near calls resolve with base 0x81D0); DS = data-segment offset, DATA.OVL file offset = DS + 0x10.

## 1. Verdict

* The original DOES call `party_random_damage` (K:2AA8) for the cactus OUCH. The notes
  (`re/notes/cactus-ouch-acta.md`, `re/notes/kernel-survival.md` 232-236) are RIGHT about the helper and about
  "rand(1,8) per living member". The ledger text of D-89 is right about the divergence.
* The reference (TypeScript) is half-right: the ON-FOOT OUCH (`game.ts:1519-1528`) calls `partyRandomDamage`
  (correct), but the NAVAL OUCH (`game.ts:1929-1933`) rolls ONE `rand(1,8)` on the active member only (wrong). Its own
  comments claim the opposite (`game.ts:1522`, "MISMA rutina que usa el cactus NAVAL"; `transport.ts:435`,
  `game.ts:1836-1838`). `re/deliberate-divergences.md:825-828` already records this as an unmeasured
  "Minor Class C"; the binary now measures it.
* Native is wrong in the same place: `native/core/src/commands.cpp:373-381` (`naval_step`). The native ON-FOOT path
  (`commands.cpp:498-509`) is right (`party_random_damage(c.game, rand)`).
* WHICH SIDE IS WRONG: the notes are right; TypeScript (naval path only) and native (naval path only) are wrong; the
  ledger entry D-89 is a correct description of the native defect, but its framing ("skiff or ship") is slightly
  off, see next bullets.
* What the "naval case" really is: there is no separate naval OUCH routine. There is ONE blocked-move tail
  (MO:0312-0347) inside MO:01FE shared by every vehicle and by walking. The OUCH branch is reached by any vehicle
  that is NOT sailing (`[0x5955] == 0`): foot, horse, carpet, skiff (0x28-0x2B), and a ship with its sails down
  (0x24-0x27, "Rowing!"). A ship UNDER SAIL (0x20-0x23, `[0x5955] != 0`) never reaches OUCH: it takes the
  COLLISION!/BREAKING UP!/Docked! branch with hull damage `rand(1,30)` (MO:109E), a different routine.
  So "naval OUCH" = a skiff or a rowed ship pushing into a cactus tile (0x2F).
* Reachability caveat (not a reason to skip the fix): in the stock overworld map (256x256, game/assets/maps/overworld.json)
  there are 14 cactus tiles (0x2F) and NONE has an orthogonal neighbour a skiff/ship can enter (tile < 4 or
  0x60-0x6F), so the naval OUCH is unreachable on stock Britannia; it is reachable via synthetic tests,
  the Developer teleport + terrain editing, and the parity corpus.
* One thing the ports also lack, and which the task asked about: per damaged member the binary flashes the party
  panel row and plays NB(10,1600,2000) (`combat-damage` cue). Neither port emits that for the OUCH (foot or naval).
  This is SFX presentation, separate from the HP/RNG defect (section 7, optional).

Confidence: HIGH for the binary facts in section 2 (every address quoted, positive controls passed). MEDIUM for the
adjacent observations flagged "adjacent" (section 8).

### 2.2 The routine that owns the OUCH: MAINOUT 0x01FE (0x01FE-0x0353, 342 bytes, ret 4)

Single caller in the whole binary (callers_banda, all bands, kernel 0x83CE): `MO:0514 call 0x01fe`, inside the
outdoor move handler MO:0490 (`ret 4`, kernel 0x8660, single caller MO:0BB3). 0x01FE is not an overlay thunk target,
so no other overlay can reach it.

Arguments (Pascal, pushed by MO:050E-0514 as `push [bp-4]` then `push [bp-6]`): in 0x01FE `[bp+6]` = dx (east/west),
`[bp+4]` = dy (north/south). MO:0490 maps its key code (bp+6) 1 = West (dec dx), 2 = East, 3 = North (dec dy, echo DS
0x29DB), 4 = South. Globals: `[0x5896]` = X, `[0x5897]` = Y, `[0x5895]` = floor, `[0x587C]` = g_transport_tile,
`[0x5955]` = g_sail_dir, `[0x585B]` = party size, `[0x587B]` = active member, `[0x5C5F]` = ship hull byte.

Instruction walk (quoted; return value `[bp-2]`):

Key facts that follow:

1. The OUCH test is on the destination TILE from the 11x11 view buffer (stride 32, party at (5,5), base 0xAB02;
   0xABA7 = party cell; callers of the same buffer: CMDS 0xB28/0xB59, TOWN 0x67A). Not on the vehicle.
2. OUCH is reachable for every `[0x5955]==0` vehicle that is blocked by a cactus: foot (0x1C/0x1D), horse (0x10-0x13),
   carpet (0x14-0x17), skiff (0x28-0x2B), rowed ship (0x24-0x27). K:2C4C returns 0 for tile 0x2F in all of them
   (DATA.OVL bit table DS 0x54D4: byte for tile 0x2F is 0xF3, mask 0x01 set = blocked; ship class 6 allows only tile<=2;
   skiff class 5: a special case for tiles 0x34-0x37, else K:2C2E (tile<4 or 0x60-0x6F) then tile<0x60).
3. `[0x5955]` writers (imm16 census): MO:0016 (clear at init), MO:0308 (clear on sailing collision/dock), MO:04AD (set to the
   key code, only when `(vehicle&0xFC)==0x20`, MO:049B), MO:0C1D (clear after every command when `(vehicle&0xFC)!=0x20`),
   K:320B (clear). So `[0x5955]!=0` implies a sails-up ship (0x20-0x23); a furled ship (0x24-0x27), a skiff and
   foot always have it 0 when 0x01FE runs.
4. "Blocked!" is printed in EVERY non-sailing blocked move that is not the whirlpool-silent exit; OUCH adds a second
   line; the bump beep and OUCH are mutually exclusive.
5. The return value is 0 on every blocked path, and MO:0490 returns it (`[bp-2]`, MO:053C-0592) to the outdoor loop.

### 2.3 What the loop does with a 0 return: NO clock tick

MO:0BB3 `call 0x490` -> MO:0BB6 `jmp 0c0f` -> MO:0C0F `mov [bp-8],ax`; MO:0C30 `cmp [bp-8],0 ; jne 0c39 ; jmp 0d14`.
The clock advance `push 2; call K:4F7C` is at MO:0C39-0C3D, reached only on a non-zero return. A cactus bump therefore
consumes no minutes and no world turn, no housekeeping, no random-hazard roll (`re/notes/kernel-survival.md:218-219`
says the same). The wind/getkey tick at the top of the loop (K:5910) still runs on the next iteration, as for any
blocked step.

Before 0x01FE runs, MO:0490 has already (a) for foot `[0x587C]==0x1C` or `(vehicle&0xFE)==0x12` played the footstep
(K:433E, `call 0xffffc16e` at MO:04C8: two noise bursts, MO:0490-04C8), (b) printed the direction echo (MO:0507 etc.)
when `[0x5955]==0`, after `call 0xda` (the turn/"Ride/Fly/Row/Head" routine) returned 0.

### 2.4 The helper K:2AA8 (`party_random_damage`) — exact semantics

```
2aa8 55 8bec 83ec04 57 56        prologue
2ab0 2bf6                         si = 0                       (member index)
2ab2 bf b355                     di = 0x55B3                   (&member[0].status; stride 0x20)
loop 2ab5:
2ab7 a05b58 ... 3bc1 7315        if si >= [0x585B] (byte, unsigned, "jae") skip     <- party size
2ac1 803d44 / 7410               if byte [di] == 0x44 ('D') skip                    <- dead members skipped, NO draw
2ac6 push si ; push 1 ; push 8 ; call 0x2092 ; push ax ; call 0x2a52   <- ONE rand(1,8) PER LIVING MEMBER, then apply(member,dmg)
2ad6 add di,0x20 ; inc si ; cmp si,6 ; jl loop                                      <- hard bound 6
```

RNG K:2092 (`rand(lo,hi)`, Pascal: first push = lo (bp+6), second = hi (bp+4); exactly ONE seed step per call):

```
2098 ax=[0x5420]; add ax,0x9248; ror ax,1 x3 (16-bit rotate right by 3); xor ax,0x9248; add ax,0x11; [0x5420]=ax
20ad and ax,0x7fff ; cx = hi-lo+1 ; xor dx,dx ; div cx ; dx += lo ; return dx
```
With rand(1,8): `value = ((seed' & 0x7fff) % 8) + 1`. Worked draw sequence, seed 0x0C4C: 4, 8, 3, 8, 5, 3, 1, 1.
(Checked: matches `OriginalRng.nextRaw16` in `game/src/core/rng-original.ts:64`.)

Apply K:2A52 (`apply_damage(member, dmg)`, bp+6 = member, bp+4 = dmg):

```
2a56 push [bp+6]; call 0x2a28          panel flash (invert rect for this member row)
2a5c push 0x0a; push 0x640; push 0x7d0; call 0x223c   = noise_burst(10,1600,2000)   (own PRNG [0x545C], does NOT touch [0x5420])
2a6b push [bp+6]; call 0x2a28          un-flash
2a71 si = member<<5 ; sub word [si+0x55b8],dmg           (HP word at record +0x10)
2a7f cmp word [si+0x55b8],0 ; jg 2aa0  (SIGNED: HP>0 -> done)
2a86 HP = 0 ; byte [si+0x55b3] = 0x44 ('D')
2a91 if [0x587b] == member then [0x587b] = 0xff        (active member cleared)
2aa0 call 0x2900                       party-panel refresh (no RNG)
```

Consequences:

* Targets: EVERY non-dead member with index < party size, not just the active one. Order: ascending slot. One draw
  per living member, drawn immediately before that member's damage, interleaved with flash/noise/refresh (these
  consume no game RNG; the noise uses its own seed at [0x545C]). I verified by census that the only K:2092 call
  reachable in this path is K:2ACF (callers_banda 0x2092 in ULTIMA.EXE: 2ACF, 2F70.., none in 0A70-0BF9, 1850-1B93,
  223C-22BF, 2726-2A52).
* Death: HP - dmg <= 0 -> HP 0 and status 'D'; active member reset to 0xFF if it died. HP is compared as a signed word.
* An already-dead member ('D') is skipped before the draw: it costs no RNG and no damage.
* Poison ('P') is neither applied nor changed; sleep ('S') is NOT woken (the status byte is only written on death).
  Sleepers and poisoned members are damaged like anyone else.
* There is no check for "party wiped": the main outdoor loop notices at the next iteration (MO:0AA2 `call K:39FC`,
  returns -1 when no member is 'G'/'P'/'S'; 1 when only sleepers remain; 0 when someone is up).
* No armour/difficulty hooks (the 1988 binary; the ports add God Mode and the A4-ENH2 starvation scaling, see 5/6).

### 2.5 Order of effects for a blocked step into a cactus

Outdoors, foot, party of N (m living members), `[0x5955]==0`, in the order the binary does them:

1. (foot only) footstep noise K:433E (MO:04C8) -- before any text.
2. (turn routine MO:00DA may print "Ride "/"Fly "/"Row "/"Head " prefixes for mounts and boats.)
3. direction echo (`North\n` DS 0x29DB...), only because `[0x5955]==0` (MO:0500-050B).
4. [ship 0x24-0x27 only] `Rowing!\n` (MO:020E), at the entry of 0x01FE.
5. K:368E object lookup, then the tile read; not passable.
6. `Blocked!\n` (MO:0322).
7. `OUCH!\n` (MO:032F).
8. K:2AA8: for each living member in slot order: rand(1,8) -> flash -> noise_burst(10,1600,2000) -> unflash -> HP update (death) -> panel refresh.
9. K:1B16 keyboard flush. Return 0. No bump beep. NO clock tick, NO world turn (MO:0C30 -> 0D14).

Text before RNG; RNG interleaved with SFX per member; clock tick never.

### 2.6 What the other naval outcomes use (for the avoidance of doubt)

* Sailing collision: MO:02F4 noise (0x64,0x7D0,0x12C), then MO:0303 `call 0x109E`.
* MO:109E: `if ((vehicle & 0xF8) != 0x20) { party_random_damage(); return; }` (MO:10A4-10AD jmp 0x1160 -> `call K:2AA8`).
  For a ship (0x20-0x27): `dmg = rand(1,30)` (`push 1; push 0x1e; call K:2092`, MO:10B0-10B8), `if (dmg < hull) { hull -= dmg; K:2900 }`
  else MO:10D6 sinks: "Ship sunk!" then skiff (`[0x5C61]>0`, tile 0x28+(v&3), "Abandon ship!"), else carpet
  (`[0x57B0]>0`, `0x14+rand(0,1)`), else MO:1120: vehicle = 0, "DROWNING!!!", then the loop MO:1148-115E:
  `K:3522(x,y)` (hit flash + noise burst, no K:2092) ; `K:2AA8` ; repeat until `K:39FC()==-1` (everyone dead). So drowning
  is also a `party_random_damage` loop, run until the party is dead. (ports: not modelled; native `transport.cpp:26`
  only sets the transport to foot.)
* `MO:0CD6` (after a successful move): tile==1 (deep water) AND skiff (0x28-0x2B) or carpet (0x14/0x15) ->
  "Rough seas!" (DS 0x2BB3), K:3522(x,y), then `call 0x109E` -> party_random_damage (non-ship branch). Not in either port.

## 7. Proposed fix and boundary test cases

Fix (smallest, no fixture churn):

* native `commands.cpp:373-381`: after `message("OUCH!")` call `party_random_damage(c.game, rand);` (default
  `starvation=false`, so Easy/Relaxed do not scale it; God Mode is already honoured inside `apply_damage`, draws still
  made, as X6 expects). Delete the local `rand(1,8)` / active-member block. Keep the whirlpool gate and the "Blocked!"
  line and the else-branch Sfx exactly as they are.
* TS `game.ts:1929-1933`: replace the `if (res.partyDamageRoll)` block with `partyRandomDamage(this.state, this.rand)`.
  Update the comments at `game.ts:1836-1838`, `transport.ts:435` ("el caller llama a partyRandomDamage"),
  `docs/FIDELITY.md:393`, `re/deliberate-divergences.md:825-828`.
* Optional (decide): emit `party-changed` / `GameEventKind::PartyChanged` after the damage, as the foot path does
  (`game.ts:1524`, `commands.cpp:503`); this regenerates `movement-flow.txt` (187 snapshots). Optional SFX parity:
  one `combat-damage` cue (NB(10,1600,2000)) per damaged member between the flash pair; needs the helper to report
  which members were hit (it is shared with starvation/fire/quake, so do it with an out-parameter or a
  presentation-side comparison of before/after HP, not by changing the draw order).

Boundary cases (write them RED first; cases 1-8 are the ones the corpus cannot see):

1. Party of 4 'G', skiff (0x2A) or rowed ship (0x25), cactus east: expect exactly 4 draws, in slot order; each member loses its own
   draw; seed after == seed after 4 steps of `rand(1,8)`. Use `OriginalRng` seed 0x0C4C: draws 4,8,3,8 -> HP -4,-8,-3,-8.
2. Same with slot 1 `'D'`: 3 draws, slot 1 untouched, slot 2 gets the SECOND draw (8), not the third.
3. Slot 2 `'S'` and slot 3 `'P'`: both damaged, both keep their status.
4. HP == draw: HP 4 with draw 4 -> HP 0, status 'D' (HP <= 0 boundary); HP 5 with 4 -> HP 1, status unchanged.
5. Active member dies: `active_character == 1`, slot 1 HP 3, draw 3-8 -> active becomes 255 (native) / 0xFF (TS).
6. `active_character` is 255 / out of range: damage is independent of it (the old code clamped to 0 here).
7. Message order: `["Rowing!"] (ship 0x24-0x27 only), "Blocked!", "OUCH!"`; skiff has no "Rowing!"; no "move-blocked" Sfx; position
   unchanged; ship hull and `sail_dir` untouched (a cactus does not damage the hull).
8. Sailing ship (0x20-0x23, `sail_dir != 0`) bumping a cactus: NO "OUCH!"; "COLLISION!" + `rand(1,30)`; one draw only (guards against an overshoot
   of the fix).
9. God Mode with 4 members: 4 draws made, no HP change, same seed as the non-God run.
10. Easy/Relaxed difficulty: damage unscaled (use the S2 pattern).
11. Whirlpool-silent exit stays: vehicle >= 0x20 and actor 0xEC..0xEF at the destination -> no text, no draw, even if the tile is a cactus.
12. Party wipe: every member dies from the sweep; the next main-loop death check must fire (binary: MO:0AA2 K:39FC == -1), no minute passes.
