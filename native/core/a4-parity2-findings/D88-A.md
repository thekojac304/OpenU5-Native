# D-88 (the combat clock) -- lens A, binary first

Investigator: lens A (disassemble and derive first, notes and ports afterwards).
Scope: read-only. Nothing in the repository was edited; no build, ctest or idf.py was run.
Scratch tooling (own copies, `d88a_` prefix) lives in `findings/d88a_work/`.
Tool commands: `d88a_dis.py <FILE> <hexoff> [<hexend>] [base=0x..]`, `d88a_census.py <hexaddr>...`,
`d88a_dsref.py <hexDS>...` (every instruction whose operand is the 16-bit DS offset).

---------------------------------------------------------------------------------------------------

## 1. Verdict

D-88 is **real**, and the binary says more than the ledger line does.

* `COMBAT.OVL` 0x0C64-0x0C76 increments a **DS byte `[0x5882]`** once per unit **activation** in the
  round loop, and when it reaches 10 it zeroes it and calls **`advance_clock(1)` (kernel 0x4F7C)**.
  It is the clock-only routine, not a world turn.
* `[0x5882]` is **persistent state**: it lies inside the 0x1060-byte `SAVED.GAM` window
  (DS 0x55A6..0x6606), at **file offset 0x2DC**. It is **never initialised at combat entry or exit**: all
  three references in all 24 binaries are those three instructions. `INIT.GAM[0x2DC] = 0`.
* The increment is before the unit acts, after its initiative counter was reloaded. Every activation counts
  (human or AI, party or monster, charmed, asleep, passing). What does not count: empty slots, flag-0x20
  slots, dead party members (who are swept and killed instead), units standing on tile 0x84/0x85
  (stocks/manacles; they do not even tick), and units whose countdown has not reached 0.
* Inside a fight `[0x5893]` (g_location) is **0xFF**, so the tail of `advance_clock` skips the sky/moon
  latch (0x4A84) and the clock-strike hook (0x71AA). What does run during the fight, immediately: minute /
  hour / day / month / year rollover, torch and light-spell minutes (-1 per minute), the hourly countdown
  `[0x588C]` (-1 per hour), the midnight Shadowlord re-roll (with RNG), the light-level recompute.
* **Meals, starvation damage and poison do not run in combat.** They live in kernel 0x2AE8
  (`turn_housekeeping`), whose only callers are the four world loops (CMDS 0x0671, DUNGEON 0x0E22,
  MAINOUT 0x0CD3, TOWN 0x10D0). They are driven by a flank on `[0x5880]` (prev_hour): written by every
  nonzero `advance_clock` (0x4FA3, before the add) and consumed by 0x2AE8 (0x2B9C). `[0x5880]` has exactly
  four references in the whole program (0x2B5D, 0x2B9C, 0x4FA3, 0x514A). Consequence: an hour crossed in
  combat is **processed only if the last nonzero advance before the next 0x2AE8 is the crossing one**. In the
  overworld Attack path (MAINOUT 0x06EC returns 0, so no advance(2) and no tick that iteration) and in every
  command-started fight in MAINOUT and TOWN, the next loop iteration runs its own advance first
  (MAINOUT 0x0C3D, TOWN 0x15D4), which overwrites `[0x5880]`: the crossing is **swallowed**. The one
  verified exception is a fight started after the iteration's advance and before its tick (the bridge-troll
  branch MAINOUT 0x0C56-0x0CD0).
* Neither port has any of this. Both already contain the counting point (TS `actionCount`, native
  `action_count`) but nothing consumes it, and both keep it **per combat object** (reset on every fight, not
  persisted).
* One tooling correction that matters for every census: **the repo's overlay-base table is wrong for
  COMBAT.OVL**. COMBAT loads at **0xA290**, not 0xBFEC (details in 2.1). `re/tools/callers_banda.py` misses
  every COMBAT caller (including this one) and 12 other overlays are affected.

Comparison with the existing notes (read after the binary work): `re/notes/combat.md` lines 66 and 82-91 already
name the same instructions (0x0C64-0x0C76), the DS byte 0x5882 and kernel 0x4F7C, and record the stocks/manacles
skip ("cell 0x84/0x85: loses the turn"); `re/notes/kernel-survival.md` sections 1-2 match my reading of 0x4F7C and
0x2AE8 line for line. Additions and corrections from this session: (1) the byte is persistent save state at
SAVED.GAM+0x2DC; (2) `[0x5893]`=0xFF turns off the sky/chime tail during a fight; (3) the by-band census that
`kernel-survival.md` calls incomplete ("2 callers") is now complete: 21 sites; (4) the repo base table error
(2.1); (5) the ledger wording "a fight that crosses an hour no longer swallows that hour's meal" is exact only
for command-started fights; a fight started between a loop's advance and its tick can still trigger the meal.

Confidence: high for sections 2-3 (every address disassembled in this session); medium for the per-entry-point
"swallow vs trigger" table (verified for MAINOUT Attack/loop and TOWN/DUNGEON loop ordering, not for every
encounter source; see 8).

## 2. Binary facts

Conventions. Overlay near-call arithmetic: call target `T = (addr+3+rel16) & 0xFFFF`, kernel address
`(T + base) & 0xFFFF`. "ovl" offsets are file offsets of the .OVL. Kernel addresses are offsets into the
34,544-byte image after the 0x800-byte MZ header (`dis16.py --exe`). DS offsets are DS offsets; a DS global
inside the save window has save-file offset `DS - 0x55A6`.

### 2.1 Positive control and the base correction (must be read before trusting any census)

* COMBAT.OVL is 7,408 bytes (0x1CF0). It has 210 `E8` sites. For base **0xA290**, 115 of the 210 land on a
  kernel `55 8B EC` prologue. For base **0xBFEC**: **0** of 210 (0xBF80: 0, 0xE1E0: 0, 0x81D0: 1).
* The thunk table (11-byte records `9A EC 02 2E 07 | id | EA lo hi 00 00`) for **id 7** has 11 records; 10 of
  their 11 targets minus 0xA290 land on a COMBAT.OVL `55 8B EC` (the 11th, 0x120E, is a prologue-less leaf:
  `B8 0F 00`). Id 7 targets: 0x7C32->ovl 0x0B94, 0x7D22->0x14D6, 0x7D2E->0x1574, 0x7D52->0x194A,
  0x7D5E->0x1A5C, 0x7D76->0x0000, 0x7D82->0x1236, 0x7E96->0x120E, 0x7EBA->0x111A, 0x7EC6->0x13E2,
  0x7EEA->0x18BA. COMBAT's span 0xA290 + 0x1CF0 = 0xBF80, which is exactly where CMDS/TALK/SJOG start.
* The repo's id 14 ("ovl 14 base 0xBFEC, 17 thunks") is **not COMBAT**: its 17 targets minus 0xBF80 land on
  prologues of **SJOG.OVL** (16/17), and id 15 is CMDS.OVL (11/12). `thunks.py --bases` takes the minimum
  target per id and mislabels.
* Empirical per-file base (best prologue-hit count of the file's own near calls; same table was reached
  independently by another agent, `u5dis.BASES`):
  0x81D0 TOWN, MAINOUT, DUNGEON; 0x81C0 INTRO; 0xA290 COMBAT, OUTSUBS, BLCKTHRN, ENDGAME, LOOKOBJ, DNGLOOK,
  SHOPPES, NPC; 0xBF80 CAST, CMDS, SJOG, TALK; 0xE1E0 CAST2, COMSUBS, ZSTATS, FONT, SHOPPES2, SHOPPES3.
  `callers_banda.py` has wrong values for COMBAT (0xBFEC), OUTSUBS (0x81D0), BLCKTHRN (0xE63E),
  ENDGAME (0xE84C), LOOKOBJ (0xA444), DNGLOOK (0xA2B6), CAST (0xA8D8), DUNGEON (0xE1E0), COMSUBS (0x85FE),
  SHOPPES2/3, INTRO, CAST2 (0xC29E).
* Positive control used for the censuses: `call 0xFFFFACEC` at COMBAT 0x0C76 resolves to 0x4F7C only with
  0xA290 (0xACEC + 0xA290 = 0x14F7C); 0x4F7C is a real prologue (`55 8B EC 83 EC 0A 57 56`) whose body reads
  the clock bytes. `call 0xFFFFDBFA` at 0x0CA6 resolves to 0x7E8A, which is a thunk record.
  With 0xBFEC the same call lands in 0x6CD8, the middle of an instruction (`D6 8A 87 14 17`).

### 2.2 The round loop: COMBAT.OVL 0x0B94-0x0D2F (thunk 0x7C32; flat 0xAE24)

Prologue `55 8B EC 83 EC 0A 57 56`. Locals: `[bp-2]` result (init 1), `[bp-8]` exit flag (init 0). Unit table:
DS 0xBA14, 32 records x 8 bytes: +0 type tile, +1 speed (DEX), +2 flags, +3 roster/monster index,
+4 object slot, **+5 initiative countdown**, +6 x, +7 y. Flags: 0x80 party, 0x40 monster, 0x20 gone/removed,
0x10 invisible, 0x08 asleep, 0x04, 0x02, 0x01 (controlled by the other side).
Creation (kernel 0x6506, 0x65A5-0x65B0 party; 0x65E5-0x65F9 monster): `[+1]=DEX`, `[+5]=0x24-[+1]`,
flags `0x80` (+`0x08` if status is not 'G'/'P'; dead members are not added) or `0x40`
(`0x20` for monster types 8 and 9); monster speed = base + rand(0..7) - 4; if that exceeds 0x1E it falls back to the base value (not a cap).

```
0ba6/0ba9/0bac/0baf  redraw 0x5910, status 0x2900, 0x1b16, thunk 0x7e8a (SJOG 0x1b6c recount)
0bb2  cmp word [0x5876],0 / jne bc0 / 0bb9 mov byte [0x58a3],1 / jmp bc5 / bc0 mov byte [0x58a3],0
0bc5  mov word [bp-8],0
0bca  mov byte [0x589e],0                    ; unit index = 0
0bcf  mov byte [0x594f],0                    ; (also the jump target of 0xd13: per unit)
0bd4..0be3  si = idx*8 + 0xba14 ; al = [si+2] ; di = ax
0be8  test al,0xc0 / jne bef / bec jmp d08   ; empty slot            -> NOT counted
0bef  test al,0x20 / je bf6  / bf3 jmp d08   ; gone                   -> NOT counted
0bf6  test al,0x80 / je c26
0bfa  bl=[si+3]; shl bx,5; cmp byte [bx+0x55b3],0x44 ; jne c26     ; party member with status 'D'
0c0a  or byte [si+2],0x20 ; push idx ; call 0x3564 ; push idx ; push 0x63 ; call 0x1574 ; jmp d08
                                                                    ; swept + killed          -> NOT counted
0c26  bl=[si+7]; shl bx,5; al=[si+6]; add bx,ax; al=[bx-0x52ec]    ; map 0xAD14 + y*32 + x
0c3a  and al,0xfe ; 0c3c cmp al,0x84 ; jne c43 ; 0c40 jmp d08       ; stocks/manacles: no tick, NOT counted
0c43  fe 4c 05          dec byte [si+5]        ; 0c46 je c4b ; 0c48 jmp d08   ; countdown not 0 -> NOT counted
0c4b  mov al,0x24 ; sub al,[si+1] ; mov [si+5],al                    ; reload 0x24 - speed
0c53  sub al,al ; mov [0x5898],al ; [0x58a2] ; [0x588f] ; [0x5890] ; [0x589d]   ; clear per-turn flags
0c64  fe 06 82 58       inc byte [0x5882]                             ; <<< THE COUNTER (8-bit, wraps at 256)
0c68  80 3e 82 58 0a    cmp byte [0x5882],0xa
0c6d  75 0a             jne c79                                        ; equality, not >=
0c6f  a2 82 58          mov [0x5882],al                                ; al is 0 here
0c72  b8 01 00 / 50     mov ax,1 ; push ax                             ; arg = 1 minute
0c76  e8 73 a0          call 0xffffacec  -> kernel 0x4f7c              ; advance_clock(1)
0c79  mov byte [0x589f],1
0c7e..0c90  push idx ; call 0x5646 ; or ax,ax ; je c90 ; call 0x3f4 (AI turn) ; (c90) call 0x63e (human turn)
0c93  [bp-0xa]=idx ; [idx+0x58a8]=0xff ; push idx ; call 0x1b1e (hazard-tile effect of the unit's cell)
0ca6  call thunk 0x7e8a  (recount: [0x5876] = AI-controlled live units, [0x5878] = human-controlled)
0ca9..0d05  exit/victory logic (see 2.7)
0d08  inc byte [0x589e] ; cmp [0x589e],0x20 ; jae cc1 ; jmp bcf     ; next unit
0cc1/d16  cmp word [bp-8],0 ; jne d1f (exit) ; jmp bca               ; next pass
0d1f..0d2f  call 0x1b16 ; mov byte [0x2186],0xff ; ax=[bp-2] ; ret
```

Facts that follow from this listing:

* **Counter variable**: DS global, byte, `[0x5882]`. Not a stack local.
* **What counts**: every unit that survives the four skip tests (empty, flag 0x20, dead party member,
  stocks/manacles tile) **and** whose countdown reaches 0 on this pass. That is one count per *activation*,
  independent of side, of control (0x5646 selects AI turn 0x03F4 vs human turn 0x063E *after* the count), of
  sleep or paralysis (those are handled inside the turn routines, after the count), of Time Stop and of
  whether the unit then acts, passes, flees or auto-passes (Set Active Player).
* **Ordering inside one activation**: reload countdown -> clear per-turn flags -> `inc [0x5882]` -> (every
  10th) `advance_clock(1)` -> turn routine. So the clock moves **before** the 10th unit acts, and the
  RNG draws of a midnight re-roll come after the previous unit's draws and before this unit's.
* **Threshold/reset**: compare is `cmp ...,0xA / jne` (equality). From 0 the sequence is 1..9, then 10 ->
  reset to 0 and advance. A loaded value >= 11 would run 255 -> 0 and reach 10 after `(256 - v) + 10`
  activations (a 1-in-256 oddity, only reachable by editing a save).
* **Nothing else in COMBAT.OVL advances the clock**: the only `call` to 0x4F7C in the file is 0x0C76; the
  turn routines (0x03F4, 0x063E, 0x14D6, 0x1574, 0x194A, 0x1A5C, 0x1B1E ...) contain none.
* **Human turn** (0x063E-0x0B93): a command loop (`[bp-4]` = finished, `[bp-2]` = restart); a blocked
  move or an invalid key re-prompts inside the same activation and counts nothing more.

### 2.3 `[0x5882]` lives in SAVED.GAM at +0x2DC

* The window: INTRO.OVL 0x0EB4-0x0EC6 reads SAVED.GAM with `push 0x31E6 (name) ; push 0x55A6 ; push
  (0x6606-0x55A6) ; push 0 ; call 0xA3AE -> kernel 0x256E` (0x256E calls 0x7234: DOS 3Dh/42h/3Fh/3Eh).
  CAST2.OVL 0x1185-0x1194 writes it with `push 0x9698 ; push 0x55A6 ; push 0x1060 ; call -> 0x25D8`
  (0x25D8 calls 0x7296: DOS 3Ch/40h/3Eh). 0x6606-0x55A6 = **0x1060 = 4192 bytes = len(INIT.GAM) = len(SAVED.GAM)**.
* `0x5882 - 0x55A6 = 0x2DC`. Neighbours (same arithmetic): year 0x5874 = +0x2CE (word), time spell 0x587A =
  +0x2D4, transport 0x587C = +0x2D6, month 0x587D = +0x2D7, day 0x587E = +0x2D8, hour 0x587F = +0x2D9,
  **prev_hour 0x5880 = +0x2DA**, minute 0x5881 = +0x2DB, **[0x5882] = +0x2DC**, hour12 0x5884 = +0x2DE,
  moon phases 0x5885/0x5886 = +0x2DF/+0x2E0, hourly countdown 0x588C = +0x2E6, time-spell turns 0x588E =
  +0x2E8, location 0x5893 = +0x2ED, floor 0x5895 = +0x2EF, light level 0x58A5 = +0x2FF, light spell 0x58A6 =
  +0x300, torch 0x58A7 = +0x301, Shadowlords 0x58C8 = +0x322, food word 0x57A8 = +0x202, party size
  0x585B = +0x2B5.
* Sanity check on the real files: `INIT.GAM[0x2CC..0x2DC] = 00 00 8B 00 00 00 00 00 00 FF 1C 04 05 08 00 23 00`
  decodes as year 0x008B = 139, +0x2D6 = 0x1C (on foot), month 4, day 5, hour 8, prev_hour 0, minute 0x23,
  **+0x2DC = 0**. The shipped `SAVED.GAM` sample also has +0x2DC = 0 (its prev_hour is 3).
* References to the byte, by instruction decode and by raw `82 58` byte scan over ULTIMA.EXE and every .OVL
  (DATA.OVL excluded): exactly COMBAT 0x0C64 (`fe 06 82 58`), 0x0C68 (`80 3e 82 58 0a`), 0x0C6F
  (`a2 82 58`). No other read or write, no block clear covering it outside the file load/save above.
  => persistent across fights, saves and loads; only returns to 0 by reaching 10 (or a fresh INIT.GAM).

### 2.4 `advance_clock` -- kernel 0x4F7C (`ret 2`, arg = minutes, word)

```
4f7c 55 8b ec 83 ec 0a 57 56
4f84 cmp word [bp+4],0 ; jne 4f8d ; 4f8a jmp 50a1             ; n==0 skips the whole add (and the 4fa3 snapshot)
4f8d cmp byte [0x587a],0x51 ; jne 4fa0                         ; 'Q'
4f94   sar word [bp+4],1 ; 4f97 cmp word [bp+4],0 ; jne 4fa0 ; 4f9d inc word [bp+4]   ; floor(n/2), min 1
4fa0 mov al,[0x587f] ; mov [0x5880],al                         ; prev_hour = hour   (BEFORE the 'T' test)
4fa6 cmp byte [0x587a],0x54 ; je 4fc8                          ; 'T': no minutes, no counter decrements
4fad mov al,[bp+4] ; add [0x5881],al                           ; BYTE add of the low byte
4fb4 push 0x58a7 ; push n ; call 0x3f36                        ; torch minutes   = sat_u8(torch - n)
4fbe push 0x58a6 ; push n ; call 0x3f36                        ; light-spell min = sat_u8(light - n)
4fc8 cmp byte [0x5881],0x3b ; ja 4fd2 ; jmp 50a1                ; unsigned > 59 ?
4fd2 sub byte [0x5881],0x3c                                    ; ONE carry only
4fd7 push 0x588c ; push 1 ; call 0x3f36                        ; hourly countdown -1 (sat)
4fe2 inc byte [0x587f] ; cmp byte [0x587f],0x17 ; ja 4ff0 ; jmp 50a1   ; hour++ ; >23 ?
4ff0 mov byte [0x587f],0                                        ; midnight
4ff5..5048  for i in 0..2: if [0x58c8+i] < 0x80:               ; Shadowlord relocation
              repeat { d = rand_range(1,8) [0x2092: push 1; push 8]   ; one draw per attempt
                       if d == [0x5893]: d = 0                       ; compare vs g_location (0xFF in combat)
                       for k in 0..2: if [0x58c8+k] == d: d = 0      ; all three slots, incl. slot i's OLD value
                     } until d != 0                                  ; unbounded retry
              [0x58c8+i] = d
5051 inc byte [0x587e] ; cmp [0x587e],0x1c ; jbe 509e           ; day++ ; > 28 ?
505c  zero [0x585a] [0x5859] [0x5858] [0x57b2] [0x5959] ; [0x587e]=1
5072  for the 16 roster records (stride 0x20) byte at 0x55bf+0x20*i : if < 0x19 then ++ ; [0x587d]++ ; if > 0xd: =1 and inc word [0x5874]
509e call 0x2900                                                 ; status-panel redraw (UI only)
50a1..513b  light level [0x58a5] (only if [0x58a5] < 0x33): 2 if [0x5893]==0x19 or [0x5895]>0x7f or hour<5 or hour>0x13;
            hour==5: ramp[min/10]; hour==0x13: ramp[(59-min)/10]; else 0x32; then >=0x12 if [0x58a6]!=0, >=0x0a if [0x58a7]!=0;
            if changed: [0x24e6] = 1
514a mov al,[0x5880] ; cmp [0x587f],al ; je 5186                 ; "hour changed in THIS call?"
5153   cmp byte [0x5893],0x21 ; jae 5164 ; 515a cmp byte [0x5895],0x80 ; jae 5164 ; 5161 call 0x4a84   ; sky strip + moon latch
5164   [0x5884] = hour==0 ? 0xc : hour>0xc ? hour-0xc : hour
5186 cmp byte [0x5893],0 ; je 5197 ; cmp byte [0x5893],0x21 ; jae 5197 ; call 0x71aa     ; clock-strike hook (driver cmd 0x6c)
5197 pop si ; pop di ; mov sp,bp ; pop bp ; ret 2
```

* 0x3F36(ptr [bp+6], n [bp+4]): `if ([ptr] > n) [ptr] -= n else [ptr] = 0` (unsigned byte compare `jbe`).
  0x3F54: same for a signed word (`jle`). 0x2092 `rand_range(lo,hi)`: LCG `s=((s+0x9248) ror 3)^0x9248)+0x11`,
  result `lo + ((s & 0x7FFF) % (hi-lo+1))`; one state step per call. 0x3AAE(n) = rand_range(0,n).
* In combat the arg is always 1, so the 'Q' branch yields 1 (not 0.5); 'T' makes the call a no-op that still
  executes 0x4FA0 (it clears any pending hour flank).
* `[0x5893]` is **0xFF during combat** (start_combat 0x5F86: `5FA8 al=[0x5893]; mov [0x5894],al` ... `5FB4 mov byte
  [0x5893],0xff`; restored at 0x6091-0x6094; DUNGEON.OVL 0x00A8 does the same before its direct call to the
  loop at 0x00C4 and restores at 0x00D5-0x00D8/0x0106-0x0109). So in a fight the 0x514A tail never calls 0x4A84
  (sky / moon-phase latch writer, the only writer of 0x5885/0x5886) and 0x5186 never calls 0x71AA. 0x4A84 itself
  also begins `cmp byte [0x5893],0x21 ; jb ... ; jmp end`.

### 2.5 `turn_housekeeping` -- kernel 0x2AE8 (meals, starvation, poison): world loops only

```
2af0 [bp-2]=0 ; [bp-4]=0 ; if [0x585b] (party size) != 0:
2b0b  for i < party size, status = [0x55b3 + 0x20*i]:
        'D'(0x44): if i == [0x587b] then [0x587b]=0xff ; no effects
        'S'(0x53): no effect, not an eater
        'P'(0x50): push i ; push 1 ; call 0x2a52 (apply_damage: 1 HP)   ; poison 1 HP per tick
        otherwise  [bp-2]++                                              ; eaters (poisoned members eat)
2b5d  al=[0x5880] ; cmp [0x587f],al ; je 2b9f                           ; FLANK: hour != prev_hour
2b66    cmp word [0x57a8],0 ; jne 2b7a
2b6d      print DS 0x54c8 ("Starving!") ; call 0x2aa8                   ; each non-'D' member (i < size): apply_damage(i, rand_range(1,8))
2b7a    else cmp hour,6 / 0xc / 0x12 (je 2b8f) ; jne 2b99
2b8f      push &[0x57a8] ; push eaters ; call 0x3f54                    ; food = sat_i16(food - eaters)
2b99    mov al,[0x587f] ; mov [0x5880],al                               ; consume the flank
2b9f  0x3ef0: [0x588b] saturating +1 (turn count) ; [0x588e] time-spell turns --, at 0 -> [0x587a]=0 + 0x2900 ; call 0x400c (ring regen)
```

* Hours with a meal: 06, 12, 18. Starvation hits on **every** hour change while food == 0.
* Callers (census, all bases tried, positive control passed): `CMDS.OVL 0x0671`, `DUNGEON.OVL 0x0E22`,
  `MAINOUT.OVL 0x0CD3`, `TOWN.OVL 0x10D0`. No kernel caller, no COMBAT caller, no SJOG caller, no function
  pointer use (literal word `E8 2A` hits are all `call` opcodes).
* `[0x5880]` references (decode + raw scan of every binary): 0x2B5D (read), 0x2B9C (write), 0x4FA3 (write),
  0x514A (read). Nothing else.

### 2.6 What a fight does to the clock, hour by hour

During the fight (every 10th activation = `advance_clock(1)` with `[0x5893]`=0xFF):

| effect | during the fight |
|---|---|
| minute / hour / day / month / year rollover | yes, immediately |
| torch `[0x58A7]`, light spell `[0x58A6]` | -1 minute per advance, saturating at 0 |
| `[0x588C]` hourly countdown (consumed by CMDS 0x03EA/0x044C, reloaded 0x0E at 0x0505) | -1 on each hour crossing |
| ambient light `[0x58A5]`, redraw flag `[0x24E6]` | recomputed |
| midnight: Shadowlord re-roll (3 slots), up to unbounded `rand_range(1,8)` draws | yes, inline in the fight's RNG stream; the "not the party's town" exclusion compares against 0xFF, i.e. never excludes |
| sky strip / moon-phase latch (0x4A84), chime hook (0x71AA) | **no** (`[0x5893]` = 0xFF) |
| meals (06/12/18), starvation damage + "Starving!", poison HP | **no** (0x2AE8 is never called) |
| `[0x588B]` turn count, time-spell turns `[0x588E]`, ring regen via 0x2AE8 | **no** |
| `[0x5880]` prev_hour | set to the pre-add hour by each advance (the flank for the next tick) |

After the fight, by entry point:

* `start_combat` 0x5F86 restores `[0x5896]`, `[0x5897]`, `[0x5895]`, `[0x5893]` (0x607F-0x6094), sets
  `[0x24E6]=1`, calls 0x2900 (0x609C) and re-copies the actor table (0x60C3-0x60E2). No clock call.
* The field-encounter wrapper `enter_combat_vs_actor` 0x6150 continues: `0x633A call 0x60EC (arena load) ;
  push 0 ; push npc ; push 0 ; call 0x5F86 ; push npc ; call 0x8016 (SJOG 0x203E: actor-table restore,
  [0x5893]=[0x5894]) ; call 0x5E4A ; push 0 ; call 0x4F7C`. That last call (kernel 0x6353-0x6356) is
  **`advance_clock(0)`**: it adds no minutes and does not touch `[0x5880]`, but it runs the light recompute
  and the 0x514A tail with the *restored* `[0x5893]`, so a pending hour flank (from the fight) triggers
  the sky strip and the moon-phase latch (0x4A84) if `[0x5893]` < 0x21 and `[0x5895]` < 0x80.
  Dungeon rooms (DUNGEON 0x0000, no advance(0)) and camp ambushes (0x3E7C -> stub 0x0E66 -> 0x3E7F) do not.
* The meal flank: the tick (0x2AE8) fires only inside a world loop, always **after** that loop's own advance:
  * MAINOUT loop (0x0A84-0x0D22): command -> `[bp-8]` = handler result -> `0x0C30 cmp [bp-8],0 ; jne 0xC39 ;
    jmp 0xD14` -> `0x0C3D advance_clock(2)` -> tile effects (0x0C56 bridge troll, 0x0C64 swamp ...) -> `0x0CD0
    call 0x0A60` -> **`0x0CD3 call 0x2AE8`**. The tick is reachable only through 0x0C3D.
  * Overworld Attack (MAINOUT 0x06EC) inits `[bp-2]=0` and never sets it, **returns 0** (`0x0789 mov
    ax,[bp-2]`), so a melee fight started with A runs no advance(2) and no tick that iteration; the next
    time-consuming command's advance(2) copies the current hour to `[0x5880]`.
  * TOWN loop: `0x15D4 advance_clock(1)` -> `0x15EC call 0x0F02` whose tail is `0x10D0 call 0x2AE8`.
  * DUNGEON loop: `0x0F2F advance_clock(1)` (reached through the 'Q' block, see re/notes dungeon.md) ->
    `0x0F84 call 0x0C76` -> tail `0x0E1F call 0x2900 ; 0x0E22 call 0x2AE8`.
  So an hour crossed by a combat advance is processed (meal at 06/12/18, starvation if food 0) **iff** the
  last nonzero advance before the next 0x2AE8 is the one that crossed it. Verified yes for the MAINOUT
  bridge-troll branch (advance(2) at 0x0C3D precedes the fight, tick at 0x0CD3 follows it); verified no for
  Attack and for any fight started by a command handler (overwritten by the next iteration's advance).

### 2.7 How a fight ends (relevant to "ends just before/after the threshold")

`0x0CA9 cmp word [0x5878],0 ; jne 0xCE8` (humans alive): `0xCE8 cmp [0x5876],0 ; jne d08` (enemies alive,
continue) else, if `[0x58A3]==0`: print DS 0x6F00 ("VICTORY!"), `[0x58A3]=1`, `call 0x4368` (victory tune),
`call 0x1B16`, then **continue the loop**. A victory does not end the fight; the fight ends only when the
human-controlled count `[0x5878]` reaches 0 (everyone left the arena / died), with `[0x5876]==0` (result 0,
0x0CB7) or after `SJOG 0x21CE` (thunk 0x7E7E, releases charmed members) returns -1 with enemies left
("BATTLE IS LOST!" 0x6EEE printed only when no "VICTORY!" was announced; result 1). So the party's walk to the edge after a victory costs activations, each
counted. The clock call for the activation happens at the start of that activation, before the unit's
escape step.
