# D-83 / D-84 -- resurrection parity (ports-first lens, investigator B)

Scope: the healer's Resurrect (D-83) and the Refuge (D-84) against the 1988 binaries, plus the other
callers of the shared routine. READ-ONLY: nothing in the repository was edited, built or run through
cmake/ninja/ctest. Everything below marked "binary" was disassembled or executed in this session from
`original/u5/ultima5/*` with the tools named in section 2.0. Scratch material is under
`.../scratchpad/findings/d83b/` (see the appendix).

---

## 1. Verdict

1. **The shared routine is `CAST2.OVL:0x05e0` `resurrect_apply(slot, mode)`** (pascal, `ret 4`). It has no kernel
   address of its own; the kernel reaches it through the 12-byte overlay stub at **CS 0x7ef6**
   (image/CS offset 0x7ef6, EXE file offset 0x86f6). (`0xdc66` in the notes is the *raw near-call operand* from the
   0xa290 band: `(0xdc66 + 0xa290) & 0xffff = 0x7ef6`; it is not a kernel address.)
2. **Exactly four callers, no other reference of any kind** (no data pointer to the stub or to 0x05e0, no intra-CAST2
   call, nothing in ULTIMA.EXE): CAST.OVL `0x10f3` (In Mani Corp **spell**, mode 0), CAST.OVL `0x12ee`
   (In Mani Corp **scroll**, mode 1), SHOPPES.OVL `0x16f5` (**healer**, mode 0xff), BLCKTHRN.OVL `0x0b95`
   (**Refuge**, mode 0xff).
3. **D-83 and D-84 are confirmed.** The healer and the Refuge both call `resurrect_apply` (status 'G', HP 1, MP by
   class, the karma < 98 experience cut, level and max HP recomputed) and **then** overwrite HP with the *recomputed*
   max HP (`SHOPPES 0x16ff-0x1703`, `BLCKTHRN 0x0b98-0x0b9d`). Both ports skip the routine and use HP 1 (healer) or the
   *stored* max HP (Refuge). The ledger rows D-83 / D-84 are exact. **The sentence in ALPHA4_UI.md section 14.5 for D-83
   ("sets HP 1 and skips resurrect_apply") describes the PORT, not the original** -- easy to misread; the original calls
   it and ends at HP = max.
4. **Arithmetic (binary, executed):** karma is an unsigned byte; `karma >= 98` (`cmp byte [0x5888],0x62 / jae`) means no
   cut. Otherwise `exp = (int16 exp * karma) / 100` via signed 32-bit multiply and truncating signed divide, stored as 16
   bits. **Level and max HP are recomputed for every karma, including >= 98**: `level = 1 + bitlength(exp/100)`
   (a `sar`/`jg` loop, no table, no cap), `maxHP = 30 * level`. For XP <= 9999 (the cap at every XP writer) level is 1..8
   and max HP 30..240.
5. **Results:** status `0x47` 'G'; HP word = 1; MP byte: class 'A' or 'M' = INT, 'B' = INT>>1, any other class unchanged;
   no RNG draw; karma never written by the routine; the only other write is the status-panel-dirty flag `[0xa9fa] = 1`.
6. **The ports' In Mani Corp arithmetic (`applyResurrect`, `apply_target_spell`) is bit-identical to the binary:** 2,075,200
   emulated runs of the real bytes (1,000,000 dense: XP 0..9999 x karma 0..99; 1,075,200 over 5 class bytes x 8 INT values x
   karma 0..255 x 105 XP values) gave 0 mismatches against both ports' models. They differ only for XP >= 32768, which no writer can produce (section 2.5).
7. **Fixture impact of the fix (measured by regenerating the reference in a scratch mirror, byte-identical positive
   control first):** `helpers.txt` 130 of 70,472 rows (all op 9, remedy 2); `flow.txt` 658 of 584,406 rows in 98
   sequences (shops 33-39); `quest_parity` 15 of 5,377 cases (the Avatar's `currentMp` 0 -> 20 only); `gameplay_parity` 0
   of 4,802; `a4_enh2_preservation` B4 golden and `batch7b` E38 change by hand-counted reasoning (section 6).
8. **Tooling warning (affects every earlier "exhaustive" census):** the base table in `re/tools/callers_banda.py` and
   in the task brief is wrong for 12 overlays (BLCKTHRN, COMBAT, CAST, COMSUBS, SHOPPES2, SHOPPES3, LOOKOBJ, DNGLOOK,
   OUTSUBS, ENDGAME, DUNGEON, INTRO; TALK and CAST2 in the tool only). `callers_banda.py 0x7ef6` reports **one** of the four
   callers. Use the PLINK86 bases (section 2.0).

Adjacent findings the implementer should know (not required for D-83/84): the scroll on a living target prints
"Not dead!" **and then** "Failed!" + glide (section 2.7); the casting ceremony for In Mani Corp lives *inside*
`resurrect_apply` (section 2.3); the ending's "X lives!" revive is a fourth, independent dead->alive path that does NOT
call the routine (already faithful in native); In Mani Corp cannot be cast in combat (mask 0x0e).

### 2.3 What each argument does (executed on the real bytes, `emu16.py`)

| record state | mode 0 (spell) | mode 1 (scroll) | mode 0xff (healer, Refuge) |
|---|---|---|---|
| status 'D' | mutate; ceremony(**8**); `[0xa9fa]=1`; return 1 | mutate; ceremony(**6**); flag; return 1 | mutate; **no ceremony**; flag; return 1 |
| status 'G','P','S' or any other byte | silent; return 0 | prints DS 0x953c "Not dead!\n"; return 0 | prints "Not dead!\n"; return 0 |
| slot < 0 | return 0xffff | return 0xffff | return 0xffff |

The comparisons are on the WORD `[bp+4]` (`cmp word [bp+4],1` at 06be, `cmp word [bp+4],0` at 0604/06ca). `mov ax,0xff` is the
word 255, not -1. The ceremony (`CAST2:0x0000`, argument < 9) is sound plus a viewport XOR; it calls the pc-speaker noise
generator (kernel 0x223c, own LFSR in `[0x545c]`) and tone sweep 0x2192, never the game RNG.

### 2.4 Record layout and the complete write set

32-byte records at `0x55a8 + 32*slot`: +0x0a class, +0x0b status, +0x0e INT (byte), +0x0f MP (byte), +0x10 HP (word),
+0x12 max HP (word), +0x14 XP (word), +0x16 level (byte). Union of every address written over 400 randomised executions:
`+0x0b, +0x0f, +0x10/11, +0x12/13, +0x14/15, +0x16` and global `0xa9fa`. **Nothing else** (no karma, gold, time, food).
(print_string and the ceremony were stubbed in the interpreter; their own screen/sound state is not modelled.)

### 2.5 Arithmetic, widths, signedness, caps

* Karma: byte `[0x5888]`, `cmp byte [0x5888],0x62 / jae` = unsigned; 0..255 all handled (>= 98 no cut). Real range 0..99
  (the karma adders in CAST2 cap at 0x63: `add byte [0x5888],al/3 ; cmp byte [0x5888],0x63 ; mov byte [0x5888],0x63` at 0x0b91-0x0b9c,
  0x0c8b-0x0c97, 0x0d05-0x0d11). The routine only reads it (`064e`, `065b`).
* XP: word `[+0x14]`, treated as **signed** (CWD before the multiply, CWD before `idiv 100`). Product is a signed 32-bit
  value; kernel `0x0442` is `mul` based (low 32 bits), kernel `0x0496` is a sign-fixing divide (dividend = top of stack,
  divisor = the pushed 100 below it). Truncation toward zero; for XP >= 0 that is floor. Result stored as 16 bits.
* XP writers cap at 9999: `COMBAT 0x193a/0x193e` and `0x1a4d/0x1a51` and `CAST 0x097a/0x097e` push `0x270f` into
  `add_word_capped` (kernel `0x3f14`: `add ax,[bp+6]; cmp ax,[bp+4]; jge -> store cap`). So XP <= 9999 in play.
* Level: `1 + bitlength(XP/100)`; thresholds XP >= 100, 200, 400, 800, 1600, 3200, 6400 give levels 2..8; level 9 would need
  12,800 (unreachable). No table, no cap in the routine. Max HP = 30*level: 30, 60, 90, 120, 150, 180, 210, 240.
* **Divergence zone (binary vs ports): XP >= 32768** (negative as a signed word). The binary then yields level 1, max HP 30
  and a wrapped XP: XP 40000, karma 50 -> as a signed word -25536; x50 = -1,276,800; /100 = -12,768 (truncating) = 0xce20 =
  **52768**; its XP/100 is negative so level 1, max HP 30. At karma 99 XP stays 40000 but the level is still 1 / max HP 30.
  The ports compute level 9..10 / max HP 270..300 instead (e.g. XP 32768 karma 50: binary 49152 / L1 / 30, ports 16384 / L9 /
  270). 624 of 728 sampled runs with XP >= 32768 differ (the 104 that agree are karma 0); 0 of 490 for XP 10000..32767.
  Unreachable through play (XP is capped at 9999 by every writer).
* Recompute runs for karma >= 98 too: it can raise a level whose XP threshold was passed but unclaimed at Lord British, and
  lower an inflated one. (E.g. XP 450, level 2, karma 99 -> level 4, max HP 120.)

### 2.6 MP, HP, status

MP only for classes 'A','M' (`MP = INT`) and 'B' (`MP = INT >> 1`, floor); every other class byte leaves MP as it was
(not zeroed). MP is a byte store; INT up to 255 gives MP 255 / 127. HP word := 1, status byte := 0x47. After the call:
healer `SHOPPES 0x16f8-0x1703` and Refuge `BLCKTHRN 0x0b98-0x0b9d` copy word `[+0x12]` to `[+0x10]` (the NEW maximum);
the spell and scroll leave HP 1.

### 2.8 Who triggers the Refuge, and for whom resurrect_apply can fire

Kernel `0x39fc` (party_conscious_state): loop slots 0..`[0x585b]`-1; status 'G'(0x47) or 'P'(0x50) -> returns 0 and stores the
slot in `[0x5876]`; counts 'S'(0x53); no G/P and some S -> returns 1; **none -> returns 0xffff (-1) = Refuge**. Entry:
the kernel trampoline `0x0e7c` (`call 0xe26 / call 0x7a5e / call 0xe1d`) called from MAINOUT 0x0af0 and DUNGEON 0x1014, and the
TOWN trampoline `0x1862` (`jmp` from TOWN 0x145c); stub 0x7a5e = BLCKTHRN:0x0910. So when the loop runs every party member is
not G/P/S: normally 'D'. A member with any other byte would get "Not dead!\n" from the routine, no status change, and STILL
`HP := max` at 0x0b98.

  SHOPPES3 0x026e inn), or a charm/unsleep release keyed on an actor flag (CAST 0x0a3e, kernel 0x682b). The inn (SHOPPES3 0x0213)
  and camp (OUTSUBS 0x080f) rest loops SKIP 'D' members. **CMDS 0x0275** (the camp ambush wake-up) writes 'G' for every
  non-poisoned *camp actor* and 'P' (0x02b7) for poisoned ones; it can only reach characters that own a camp actor, and the actor
  builder (kernel 0x69e1: `cmp byte [bx+0x55b3],0x44 / jne 69eb / jmp 6b6e`, read here) skips status 'D', so the dead are untouched. Three further `c6 02 47` matches

## 7. Proposed fix and boundary test cases

**Reference first (the layer the fixtures pin: `healerHeal` and `partyRefuge`):**
1. healer, after the payment and before returning ok: `applyResurrect(rec, state.karma); rec.currentHp = rec.maxHp;`
   (instead of `status = "G"; currentHp = 1`). Mode 0xff: no message, no ceremony.
2. Refuge loop: `if (c.status === "D") { revived++; applyResurrect(c, state.karma); } c.currentHp = c.maxHp;` and **no**
   unconditional `status = "G"` (the binary leaves a non-'D' status alone and only prints "Not dead!\n"); the karma floor stays
   AFTER the loop. (In the scratch mirror this exact patch ran clean under Node/tsx through both shop generators, 5,377
   quest cases and 4,802 gameplay cases; `shops.ts` and `blackthorn.ts` importing `magic/cast.js` caused no cycle failure.)
3. Native: extract the body of `apply_target_spell`'s Resurrect case into one `resurrect_apply(CharacterState&, uint8_t karma)`
   (declare in `magic.h`; one static library, so `shops.cpp` and `quest_world.cpp` can call it), call it from `healer_heal`
   (then `c.current_hp = c.max_hp`) and from `resolve_refuge` (same shape as TS). `-Wall -Wextra -Wconversion -Werror` applies:
   cast every u8/u16 narrowing. Add the karma-effective hook point here (a value >= 98 = no cut) when the softer-death option
   lands.

**Traps a binary-first reading misses:** (a) HP := max must read the max AFTER the routine rewrote it; (b) level and max HP are
recomputed at karma >= 98 as well (a Refuge at karma 99 can raise level from unclaimed XP); (c) the cut uses the karma at death
(the floor of 75 comes later; karma 74 still cuts 74%); (d) a Refuge member the routine rejects still gets HP := max; (e) XP is a
signed word (irrelevant under the 9999 cap); (f) no RNG, but keep pay -> drain -> effect order in the healer; (g) mode 1 / 0xff

## 8. Unresolved

* **Presentation order of the spell/scroll ceremony** (inside the routine, after the mutation, dead targets only; mode 0 -> 8,
  mode 1 -> 6) versus the ports (TS `emitCastCeremony` right after a successful cast and before the picker, unconditional;

* Whether any caller passes mode values other than 0, 1, 0xff: the four sites are exhaustive; no indirect call to the stub exists.
* XP >= 32768 behaviour is derived from the bytes but unreachable in play; whether to model the signed word is a choice
  (documented divergence is enough).
* The interpreter stubs print/ceremony; their screen state, and the pc-speaker, are not emulated. The `[0xa9fa]` consumer
