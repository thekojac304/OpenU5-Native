# Batch 47: source-pixel bed tile evidence

Generated with `node_modules/.bin/tsx re/tools/batch47_tile_sheets.ts` from shipped `original/u5/ultima5/TILES.16` (SHA-256 in `source.txt`). Each of the four `tiles-*.png` files covers 128 consecutive tiles, so all 512 were inspected. Labels are hex ID followed by decimal ID. The focused furniture, sleep, and candidate sheets use the same source pixels, canonical EGA palette, and nearest-neighbor enlargement only.

## Identification

- **0x11a / 282: definite person in bed.** The 16x16 image depicts a green-clad reclining figure, head to the left, in a blue/white bed. It begins at decompressed `TILES.16` byte `0x8d00` (= 282 x 128). Its immediate neighbors are 0x119 Moon and 0x11b Carpet2; 0x11c BasicAvatar, 0x11d Apparition, 0x11e DeadBody, and 0x11f Splat follow. `candidate-110-11f.png` shows the tight neighborhood.
- **0xab / 171 and 0xac / 172: static bed terrain, not the reclining actor.** They are the two halves of every authored town bed; 0xab has pillow and blue bedding. `furniture-080-0bf.png` shows 0xa5 (EndTable), 0xab/0xac and nearby furniture. 0x9a-0x9c are food tables, not occupied beds.
- **0x11e / 286: separate body-on-ground image.** The Camp sleep scene selects this for eligible party members; its pixels have no bed. The 0x100-0x13f sheet makes the difference visible.

Normal source palette is canonical 16-color EGA with brown fix. The tile is opaque at the source level (16x16 packed 4bpp). Original `EGA.DRV` also names 0x11a in its endgame recolor list: file offset 0x2d16 loads `SI=0x8d00`, then calls the recolor routine at 0x2d5d. That is a palette transformation, not a separate tile or proof that the endgame places a bed occupant.

## Original use and scope of the search

The original executable's actor placement routine `ULTIMA.EXE` image 0x51b8-0x5391 reads the terrain under an eligible actor. At 0x5356 it compares terrain with 0xab and branches to 0x529a, which writes render byte **0x1a**. The routine stores that byte at 0x537a-0x537d. Its caller is the object-composition loop at 0x55fe. The actor-bank blit (`FONT.OVL` 0x02ce-0x02f1) adds 0x100 to the render byte, producing **0x11a**. This is an indirect tile reference; a search for literal word 0x011a alone would miss it. The actor-type gate at EXE 0x51bf-0x51e6 bypasses this terrain selection for ordinary NPC type bytes >= 0x40, consistent with Batch 45's upright scheduled occupants. The original `CMDS.OVL` bed-sleep command uses terrain 0xab but does not select 0x11a itself; its viewport becomes black during sleep. The generic visible pose applies when an eligible party actor stands on the bed head.

`shipped-left-beds.csv` enumerates every 0xab cell in the four shipped 32x32 town-map files with location, floor, coordinates, adjacent tile IDs and *possible* overlap with any of that location's authored NPC schedule posts. There are **264** such cells across **29** locations, all followed by 0xac on the right; **240** have at least one NPC schedule post in some period (not necessarily the current hour). Examples: Lord British's Castle floor 0 (9,7) has slot 13 type 0x5c; (17,7) has guard slot 1 type 0x70; (12,10) has slot 14 type 0x50. Iolo's Hut floor 0 (12,14) is an unassigned reachable bed. `castle-bed-static-x9y7.png` is an exact 7x7 shipped terrain crop around the castle bed. `castle-bed-pose-illustration-x9y7.png` replaces only (9,7) with 0x11a to explain the original branch; it is an **illustration, not a captured 1988 frame**.

No 0x11a is stored as a town-map cell: these files contain one byte per cell, and the actor tile is selected by code. All 32x8 shipped .NPC type bytes were decoded; **zero** equal 0x1a. The endgame driver recolor entry and the executable's dynamic actor selection are the recovered semantic code references. The intro/demo notes describe the actor bank generally, but the decoded shipped demo script uses 0x1e in its summoning scene; no 0x1a PLACE was recovered. The inn rest path (SHOPPES3.OVL 0x0164/0x016b) writes room X/Y from six-entry DATA.OVL tables but has no recovered 0x1a tile writer. Any 0x11a there follows the common world pose selector when the party actually stands on a bed head. Camp uses 0x11e, not 0x11a.

The native world path currently passes its fixed on-foot `tile_report_.avatar_tile` into `compose_world_presentation`; the latter unconditionally writes it to the center cell without inspecting 0xab. That is a distinct, queued preservation gap (H-181/D-38). Batch 47 changes no production renderer or sleep behavior.
